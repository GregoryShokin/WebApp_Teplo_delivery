# Архитектура Google Sheets ДДС

Дата анализа: 2026-05-20.

Источник: Google Sheets `Копия 01. ДДС — Классический • ИП Шокина`, режим read-only через Google Drive connector и XLSX-снимок. Исходная таблица не изменялась. Строки платежей, назначения, ФИО, счета, договоры и контрагенты в этот файл не переносились.

Важно: старый ДДС содержит факт за 2023-08 - 2023-12. Его можно использовать как прототип структуры и формул, но нельзя использовать как факт 2026.

## Карта листов

| --- | --- | --- | --- | --- |

| `ДДС: месяц` | Главный журнал операций | Ручной ввод + формулы | Денежные операции по датам, кошелькам, статьям, направлениям; формульные месяц, тип движения, вид деятельности; текущие остатки по кошелькам | Высокий для строк, средний для агрегатов |

| `Справочники` | Малые справочники | Справочник, ручной | Направления бизнеса, виды деятельности, группы `Поступление` / `Выбытие`, маппинг номера месяца в название | Низкий |
| `Контрагенты` | Список контрагентов | Справочник, ручной | Список контрагентов для выбора в журнале | Высокий |
| `Технический лист` | Технические списки | Служебный, скрытый | Номера/названия месяцев и вспомогательные последовательности для автозаполнения | Низкий |
| `Сводная по направлениям` | Заготовка аналитики по направлениям | Почти пустой / не используется | В XLSX-снимке значимой структуры нет; поле `Направление бизнеса` в журнале пока не доведено до полноценной сводки | Агрегаты |

## Строка операции в `ДДС: месяц`

Диапазон операций начинается с `A5:K`. В строках операций есть ручные поля и формульные поля:

| Колонка | Поле | Тип | Логика |
| --- | --- | --- | --- |
| `A` | `Месяц` | Формула | `ARRAYFORMULA`: если дата заполнена, берет название месяца через `VLOOKUP(B; Справочники!E:F)` |
| `B` | `Мсц (цифрой)` | Формула | `ARRAYFORMULA`: `MONTH(C)` |
| `C` | `Дата` | Ручной ввод | Дата операции, есть проверка `DATE_IS_VALID` |
| `D` | `Сумма` | Ручной ввод | Подписанная сумма: поступления положительные, выплаты отрицательные |
| `E` | `Кошелек` | Ручной выбор | Dropdown из `ДДС: настройки (для ввода сальдо)!A3:A13` |
| `F` | `Направление бизнеса` | Ручной выбор | Dropdown из `Справочники!A2:A`; в старой таблице направления есть, но отдельная сводка почти не реализована |
| `G` | `Контрагент` | Ручной ввод / выбор | Персональные и коммерческие данные; в выгрузки не выносить построчно |
| `H` | `Назначение платежа` | Ручной ввод | Высокая приватность; в приложение переносить как private/comment field, в отчеты не раскрывать |
| `I` | `Статья` | Ручной выбор | Dropdown из `ДДС: статьи!A2:A227`, strict validation |
| `J` | `Платеж/поступл` | Формула | `ARRAYFORMULA` + `VLOOKUP(I; ДДС: статьи!A:D; 2)` возвращает `Поступление` или `Выбытие` |
| `K` | `Вид д-ти` | Формула | `ARRAYFORMULA` + `VLOOKUP(I; ДДС: статьи!A:D; 3)` возвращает `Операционная`, `Инвестиционная`, `Финансовая`, `Техническая операция` |

Вверху листа `A1:I3` есть текущие остатки по кошелькам. Формула каждой суммы: `SUMIFS(Сумма; Кошелек; выбранный кошелек) + начальное сальдо из настроек`. `A3` суммирует кошельки и дает общий остаток.

| `Сейф` | Наличный сейф / касса | 13,936.78 |

## Остатки и cashflow

Логика локального кошелька одинакова для всех листов кошельков:

1. `Денег на начало месяца`: если месяц равен стартовому месяцу из настроек, берется начальное сальдо; если месяц позже стартового, берется остаток на конец прошлого месяца; если раньше, 0.
2. Строки статей: суммы считаются через `SUMIFS` по `ДДС: месяц`, где совпадают месяц, кошелек и статья.
3. `Изменение денег за месяц`: сумма операционного, инвестиционного, финансового и технического блоков внутри кошелька.
4. `Денег на конец месяца`: начало месяца + изменение месяца.

`ДДС: Сводный` считает общий ДДС так:

| Блок | Диапазон | Логика |
| --- | --- | --- |
| Начальные остатки | `B2:M14` | Сумма начальных остатков по кошелькам, по месяцам |
| Операционная деятельность | `B15:M115` | Статьи из `ДДС: статьи` с видом `Операционная` |
| Инвестиционная деятельность | `B116:M126` | Статьи с видом `Инвестиционная` |
| Финансовая деятельность | `B127:M217` | Статьи с видом `Финансовая` |
| Изменение денег за месяц | `B218:M218` | `Операционная + Инвестиционная + Финансовая` |
| Денег на конец месяца | `B219:M219` | `Денег на начало + Изменение денег` |
| Локальные ДДС | `B220:M232` | Конечные остатки по каждому кошельку, рассчитанные напрямую по журналу операций |
| Проверка сходимости | `B233:M233` | `IF(ROUND(Денег на конец - Итого в локальных ДДС)=0; "OK!"; difference)` |
| Переводы между счетами | `B234:M236` | Проверка, что поступления и выбытия по внутренним переводам взаимно обнуляются |

По старому анализу агрегатов `gs_cashflow_monthly.csv` сводка сходится не во все месяцы: 2023-08 расхождение 270,000; 2023-11 и 2023-12 расхождение по 75,000. Причина не в локальных кошельках, а в том, что часть операций меняет остатки, но не попадает в операционный/инвестиционный/финансовый блок сводного ДДС.

Выявленная конкретная причина: статья `Услуги ФД` встречается в журнале, но в справочнике `ДДС: статьи` есть близкая, но не идентичная статья `Услуги ФД и НК`. Из-за строгого `VLOOKUP` такие строки получают ошибку классификации и выпадают из расчетного cashflow, хотя кошелек по сумме меняется.

## Что переносить в веб-приложение

Переносить нужно не сами формулы как spreadsheet-код, а правила:

- валидируемый журнал операций с датой, signed amount, кошельком, статьей, контрагентом, назначением, направлением;
- автоматическую классификацию операции из статьи: `movement_type` и `activity_type`;
- начальные остатки по кошелькам на дату/месяц старта;
- monthly roll-forward: начало + обороты = конец;
- разделение cashflow на operating / investing / financing и технические операции;
- сверку общего остатка с суммой остатков кошельков;
- отдельную сверку внутренних переводов;
- контроль неизвестных статей и запрет попадания операции в отчет без валидной статьи;
- приватность назначения платежа и контрагента: в отчетах показывать агрегаты, в карточке операции хранить доступно только авторизованным ролям.
