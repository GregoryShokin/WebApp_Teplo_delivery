# Структура листа `Персональный отчет`

Источник изучен read-only: Google Sheets `Расчет зарплат NEW`.
ФИО, телефоны, персональные суммы и персональные истории в этот файл не вынесены.

## Назначение

`Персональный отчет` — это не просто отчет за выбранный период. В нем смешаны:

- периодная детализация по дням;
- накопительный баланс/долг сотрудника с датами отсечения;
- расчет текущей суммы к выплате;
- отдельный блок накопительного фонда;
- подсказка к выплате накоплений в январе.

Главные входы:

| Ячейка | Назначение |
|---|---|
| `A2` | начало периода |
| `B2` | конец периода |
| `E2` | выбранный сотрудник |

## Верхний блок итогов

| Блок | Ячейки | Смысл |
|---|---:|---|
| `Задолженность на начало` | `E3:F3` | баланс до даты `A2` по сотруднику |
| `Задолженность на конец` | `E4:F4` | баланс до даты `B2` включительно |
| `Долг сотрудника` | `A4:B4` | расчет долга/переплаты сотрудника с учетом текущего периода |
| `За N смены начислено` | `E5:F5` | сумма видимых начислений за строки периода: оклад, процент, премия, больничные/отпуска/пособия, накопительный фонд минус штрафы по ревизиям |
| `К Выплате` | `A7:B7` | текущая сумма к выплате по формуле баланса; накопительный фонд в этот расчет не включен |
| `Выплата долга` | `D7:E7` | появляется, если есть удержание в уплату долга |
| `Накопления` | `G7:H7` | накопительный фонд за текущий год минус `Списание накоплений` за текущий год |
| `Выплата 15 января` | `I7:J7` | подсказка к выплате накоплений за предыдущий год в январском окне |

Важная особенность: `F3` добавляет `Накопительный фонд` в задолженность на начало, а `F4` и `B7` его не добавляют. Это выглядит как осознанное разделение "накоплено" и "к выплате", но требует подтверждения владельца, потому что формулы не полностью симметричны.

## Детальная таблица

Строка `8` задает типы колонок:

| Колонка | Тип |
|---|---|
| `A` | дата |
| `B` | `Оклад` |
| `C` | `Процент` |
| `D` | `Премия` |
| `E` | комментарий к премии |
| `F` | `Больничные и отпуска и пособия` |
| `G` | `Накопительный фонд` |
| `H` | `Депозит возврат` |
| `I` | `Депозит удержание` |
| `J` | `Штрафы и удержания` |
| `K` | комментарий к штрафу |
| `L` | `Штрафы по ревизиям` |
| `M` | `Удержание НДФЛ`, фактически ищет `НДФЛ Начислено` |
| `N` | `Выплата ЗП` |
| `O` | `Выплата аванса` |

`A9:A` строится как список уникальных дат из технического календаря в диапазоне `A2:B2`.

Для начислений в `B:D`, `F:J`, `L:M` используется один шаблон:

```text
SUMIF(
  'Выгрузка'!A:A & 'Выгрузка'!C:C & 'Выгрузка'!F:F,
  дата_строки & выбранный_сотрудник & тип_колонки,
  'Выгрузка'!B:B
)
```

Для выплат в `N:O` используется аналогичный шаблон по листу `Выплаты`:

```text
SUMIF(
  'Выплаты'!A:A & 'Выплаты'!C:C & 'Выплаты'!F:F,
  дата_строки & выбранный_сотрудник & тип_колонки,
  'Выплаты'!B:B
)
```

Комментарии к премиям и штрафам подтягиваются через `VLOOKUP` из `Выгрузка!G:G` по дате, сотруднику и типу. Если за один день есть несколько комментариев одного типа, формула покажет только первое найденное значение. Для веб-приложения это лучше заменить списком source line ids.

## Какие строки из `Выгрузка` попадают

Строка из `Выгрузка` попадает в дневную часть отчета, если:

- `Выгрузка!A` попадает в период `A2:B2`;
- `Выгрузка!C` равен выбранному сотруднику `E2`;
- `Выгрузка!F` равен одному из типов строк отчета: `Оклад`, `Процент`, `Премия`, `Больничные и отпуска и пособия`, `Накопительный фонд`, `Депозит возврат`, `Депозит удержание`, `Штрафы и удержания`, `Штрафы по ревизиям`, `НДФЛ Начислено`;
- сумма берется из `Выгрузка!B`;
- комментарий, если нужен, берется из `Выгрузка!G`.

Для верхних балансов используются те же поля, но с другими датами отсечения:

- начало: `Выгрузка!A < A2`;
- конец: `Выгрузка!A <= B2`;
- часть расчетов `К Выплате` сделана кумулятивно по сотруднику, а не только по выбранному периоду.

## Обезличенный пример структуры отчета

```text
Период: [дата начала] - [дата конца]
Сотрудник: [employee_id / обезличенное имя]

Задолженность на начало: [amount]
Задолженность на конец: [amount]
Долг сотрудника: [amount]
Начислено за N смен: [amount]
К выплате: [amount]

Дата | Оклад | Процент | Премия | Комментарий | Больничные/отпуска/пособия | Накопительный фонд | Депозит возврат | Депозит удержание | Штрафы | Комментарий | Ревизии | НДФЛ | Выплата ЗП | Выплата аванса
```

## Рекомендация для веб-приложения

Дневная таблица должна показывать не только агрегированную сумму, но и раскрытие до исходных строк:

- `ledger_line_id`;
- дата события;
- расчетный период;
- источник (`Калькулятор`, `Зарплата Администрации`, ручная корректировка, импорт выплат);
- тип строки;
- сумма;
- знак влияния на баланс;
- комментарий;
- автор/импорт;
- ссылка на событие смены, выплату, штраф, депозит или ручную корректировку.

Такой audit trail заменит текущую потерю детализации в `SUMIF` и `VLOOKUP`.
