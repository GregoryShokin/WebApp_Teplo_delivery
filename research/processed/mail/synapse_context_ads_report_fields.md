# Синапс / Biz Panel: данные для статистики рекламных кампаний

Дата проверки: 2026-05-22.

## Почтовый источник

Локальная синхронизация ящика `g.shokin@mail.ru` содержит еженедельные письма от
`hello@biz-panel.com` с темой `Синапс. Отчет по рекламе в Яндекс.Директ, Google Ads и SEO-продвижению.`

Проверенный диапазон писем: `2025-11-03`-`2026-05-18`, всего 29 отчетных писем.
Вложения в этих письмах не сохранены: письмо дает свежую ссылку входа в Biz Panel, а сами данные лежат в кабинете.

Безопасная логика доступа без хранения одноразовой ссылки:

```text
письмо hello@biz-panel.com
-> свежая ссылка входа в Biz Panel
-> договор CNTX-212566 от 25 Мар. 2021г.
-> вкладка Яндекс
-> https://biz-panel.com/node/59505/yandex?begin=YYYY-MM-DD&finish=YYYY-MM-DD
```

Счета:

```text
Biz Panel -> договор CNTX-212566 -> вкладка Счета
https://biz-panel.com/node/59505/download-invoice/{invoice_number}
```

## Что можно доставать из отчетов

### 1. Агрегат по периоду

Эти поля подходят для общей динамики по каналу Яндекс.Директ:

| Поле | Назначение |
| --- | --- |
| `period_start`, `period_end` | календарный период отчета |
| `project` | проект/рекламируемый бизнес, в проверенном отчете `Теплофуд` |
| `platform` | `yandex_direct`; потенциально из письма также есть `google_ads`, если договор/кабинет содержит данные |
| `impressions` | показы |
| `clicks` | клики |
| `spend_rub` / `budget_rub` | поле `Бюджет`; фактический расход рекламных кампаний за период |
| `ctr` | клики / показы; можно брать из отчета, но лучше пересчитывать из строк |
| `cpc_rub` | расход / клики |
| `daily_spend_rub` | средний расход в день |

### 2. Разбивка по кампаниям

Это главный слой для статистики рекламных кампаний:

| Поле | Назначение |
| --- | --- |
| `campaign_name` | название кампании |
| `network` | выводится из названия/кабинета: например `SEARCH` или `AD_NETWORK` |
| `impressions` | показы кампании |
| `clicks` | клики кампании |
| `spend_rub` / `budget_rub` | расход кампании |
| `ctr_calc` | `clicks / impressions` |
| `cpc_calc_rub` | `spend_rub / clicks` |
| `cpm_calc_rub` | `spend_rub / impressions * 1000` |
| `spend_share` | доля кампании в расходе периода |
| `click_share` | доля кампании в кликах периода |
| `impression_share` | доля кампании в показах периода |
| `is_zero_spend` | контроль кампаний с кликами/показами, но нулевым расходом в отчете |

### 3. Топ запросов

В письме Синапса явно указано, что в кабинете есть `Топ-10 запросов, по которым перешли на ваш сайт в отчетном периоде`.
Для статистики стоит забирать минимум:

| Поле | Назначение |
| --- | --- |
| `search_query` | поисковая фраза/запрос |
| `period_start`, `period_end` | период |
| `platform` | `yandex_direct` |
| `campaign_name` | если Biz Panel связывает запрос с кампанией |
| `clicks`, `spend_rub`, `cpc_rub` | если эти метрики доступны в таблице топ-10 |

Если в Biz Panel топ-10 дает только список запросов без метрик, хранить как справочник спроса и использовать для семантики.

### 4. Документы и счета

Счета нужны не как замена фактического расхода кампаний, а для P&L и сверки оплат:

| Поле | Назначение |
| --- | --- |
| `invoice_number`, `invoice_date` | номер и дата счета |
| `service_period` | месяц услуги |
| `invoice_total_rub` | сумма счета |
| `subscription_fee_rub` | абонентское обслуживание Синапса |
| `placement_invoice_rub` | строка размещения/пополнения Яндекс.Директ из счета |
| `payment_date`, `payment_amount_rub` | сверка с T-Bank |
| `legal_counterparty` | для контекста проверено ООО «О. О» |

Правило учета, подтвержденное 2026-05-22:

```text
Контекстная реклама =
абонентское обслуживание Синапса из счета за месяц услуги
+ фактический Бюджет кампаний из Biz Panel за календарный период
```

Строку размещения рекламных материалов из счета использовать как сверку платежа/пополнения, но не как замену фактического `Бюджета`.

### 5. Задачи и доступы

В письме также заявлены:

| Блок | Как использовать |
| --- | --- |
| текущие задачи по рекламе | контроль выполненных работ подрядчика и объяснение изменений в метриках |
| доступы в рекламный кабинет Яндекс.Директ | источник для подключения прямой выгрузки в будущем |
| закрывающие документы | документная сверка P&L |
| заявка на аналитику РК | ручной канал получения расширенной аналитики за месяц |

### 6. Не смешивать с SEO и поддержкой сайта

В том же письме есть SEO и сайтовые блоки, но это отдельные контуры:

| Контур | Данные |
| --- | --- |
| SEO | история позиций по запросам, сравнение по регионам и поисковым системам, количество запросов в ТОП-10 и ТОП-30, задачи, неоплаченные счета |
| информационная поддержка сайта | трафик активности пользователей, входящие заявки с сайта |

Для строки P&L `SEO - оптимизация` первичный почтовый источник другой: `webmaster@insaitov.ru`.

## Что нужно для CAC / ROMI по кампаниям

Сам отчет Синапса дает рекламные метрики, но не закрывает экономику заказов. Чтобы считать `CPA`, `CAC`, `ROMI` и `LTV/CAC`, нужно связать отчет с сайтом/Метрикой/iiko:

| Нужно поле | Источник |
| --- | --- |
| `utm_source`, `utm_campaign`, `utm_content`, `utm_term` | сайт / Метрика / рекламный кабинет |
| `yclid` или другой click id | сайт / Метрика |
| `session_id` / `client_id` | Метрика |
| `goal_reach`, `purchase`, `order_id` | Метрика / сайт |
| `iiko_order_id`, `revenue`, `discount`, `food_cost`, `gross_margin` | iiko |
| `customer_hash`, `is_new_customer` | private customer mart |

Минимальный практичный отчет на первом этапе: `period + campaign_name + impressions + clicks + spend + orders + revenue + gross_margin`.

## Контроль качества

1. В апрельском отчете сумма кампаний по `Бюджет` сходится с общим бюджетом.
2. `CPC = Бюджет / клики` сходится с отчетом: 23 984,77 / 964 = 24,88.
3. `CTR` лучше пересчитывать самим из строк, потому что значение в отчете может относиться не ко всем строкам или быть рассчитано по внутренней логике Biz Panel.
4. Письма от `hello@biz-panel.com` не считать первичным файлом данных: это входная точка в Biz Panel.
