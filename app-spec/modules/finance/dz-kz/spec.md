# Спецификация модуля Учёт ДЗ/КЗ поставщиков

Дата сборки: 2026-05-24.  
Последнее обновление: 2026-05-25 (источник 2025/2026 признан неактуализированным; для MVP разрешен manual opening register поставщиков на 2026-02-01).

## Назначение

Модуль `Учёт ДЗ/КЗ поставщиков` фиксирует взаиморасчёты с поставщиками на стыке P&L, ДДС и Баланса:

- признанные расходы периода по документам/правилам accrual;
- оплату поставщикам из ДДС;
- остаток кредиторской задолженности перед поставщиками;
- остаток дебиторки поставщиков / выданных авансов поставщикам.

Текущий Google Sheets называется в HTML `2024 Учёт ДЗ и КЗ поставщиков [ИП Шокина]`; со слов владельца рабочее название источника — `Учёт дебиторской и кредиторской задолженности` (`УДКЗ`). Это не общий модуль всей дебиторки/кредиторки бизнеса: файл покрывает именно поставщиков и статьи ОПиУ, а не займы собственникам, сотрудников, налоги или клиентов. Для приложения УДКЗ остаётся supplier/AP prototype: единый долгосрочный master контрагентов — общий `counterparty` с ролью `supplier`.

## 2. Структура сущностей

### `supplier_counterparty`

Источник: вкладка `Контрагенты`.

**Решение владельца 2026-05-24 (11.1)**: `supplier_counterparty` в приложении является профильным view/extension над общим `counterparty` с ролью `supplier`, а не отдельным независимым master-справочником.

**Уточнение владельца 2026-05-25 (C12)**: единый реестр поставщиков должен использоваться во всех отчётах, где выбирается поставщик: платежный календарь, DDS, УДКЗ и баланс. Технически это один `counterparty` master с ролью `supplier`; `supplier_counterparty` хранит только профильные поля поставщика и aliases. Отдельные справочники поставщиков в модулях не создаются.

| Поле в Sheets | Значение в приложении |
| --- | --- |
| `Контрагенты список` | `counterparty_id` с ролью `supplier` / supplier alias; в processed хранится только hash |
| `Статья ОПиУ` | default P&L article для контрагента |
| `Статус` | active/inactive |
| `Задолженность на 1 марта 2024 г` | opening balance: `+` кредиторка, `-` дебиторка/аванс |

### `supplier_document`

Источник: `Регистрация вход. док-тов`.

**Решение владельца 2026-05-24/25 (11.5 + C12), уточнено 2026-05-27**: УДКЗ покрывает КЗ поставщиков, supplier-based авансы и внешние префиксные остатки. `supplier_document.prepayment_kind` используется для авансов/документов поставщиков и предоплатных остатков: рекламные кабинеты, Mango/телефония, аренда, подписки, налоговые переплаты при появлении. Источники информации по типам префиксов нужно разобрать отдельно; в балансе они агрегируются как `Выданные авансы поставщикам`.

| Поле | Назначение |
| --- | --- |
| `Месяц` | месяц признания |
| `Дата` | дата входящего документа или дата признания расхода |
| `Номер акта/СФ/УПД/накладная` | private document reference |
| `Сумма` | сумма признанного расхода, всегда со знаком `+` |
| `Контрагент` | поставщик |
| `Статья` | статья ОПиУ |
| `prepayment_kind` | тип supplier-based аванса/поставочного документа; для MVP УДКЗ не становится реестром рекламных кабинетов, Mango, налоговых переплат или аренды вне supplier roll-forward |
| `Комментарий` | private note |

### `supplier_monthly_rollforward`

Источник: вкладки `01`..`12`.

| Поле | Назначение |
| --- | --- |
| `Контрагент - поставщик` | поставщик |
| `Задолженность за прошлые месяцы` | opening balance месяца; `+` кредиторка, `-` дебиторка |
| `Сумма отгрузок и оказанных услуг (ОПИУ)` | признанные расходы месяца |
| `Дата документа` / `Номер документа` | ссылка на документ/признание |
| `Оплачено в текущем месяце (ДДС)` | агрегат `supplier_payment_match.matched_amount` по платежам из DDS |
| `Дата оплат` | даты оплат из ДДС |
| `Остаток задолженности на конец месяца - БАЛАНС` | closing balance; `+` кредиторка, `-` дебиторка/аванс |
| `Статья ОПиУ` | статья для сводки |

Формула сущности:

```text
opening_balance
+ recognized_expense
- cash_paid
= closing_balance
```

Знак closing balance определяет балансовую строку:

```text
closing_balance > 0 -> Задолженность перед поставщиками
closing_balance < 0 -> Выданные авансы поставщикам
```

### `supplier_balance_summary`

Источник: `Свод`.

Вкладка содержит три секции по статьям и месяцам:

| Секция | Назначение |
| --- | --- |
| `Расходы для ОПиУ` | признанные расходы поставщиков по статьям ОПиУ |
| `Кредиторка (поставщики) для Баланса` | положительные остатки поставщиков на конец месяца |
| `Дебиторка (авансы поставщикам) для Баланса` | отрицательные остатки поставщиков, развернутые как авансы |

Owner decision 2026-05-25 для платежного планирования: для продуктовых поставщиков нужен целевой integration source/endpoint приложения к iiko, который достает неоплаченные поставки и ожидаемый timing оплаты. Важное расхождение с [old-os-and-balance-discovery.md](/research/archive/old-os-and-balance-discovery.md): в регламенте баланса `Учёт ДЗ/КЗ` помечен `FALSE`, но УДКЗ как отдельный документ существует и был заполнен за 2024 год. Значит, строка регламента баланса устарела как минимум для контура 2024. По owner decision 2026-05-25 текущая актуальность после середины 2025 не подтверждается: документ использовать как structure seed, а не как current source. Opening на 2026-02-01 закрывается manual opening register.

## 5. Методология

### Поставщик: расход, оплата, остаток

1. В `Регистрация вход. док-тов` заносится признанный расход по поставщику и статье ОПиУ.
2. В `Импорт ДДС` подтягиваются оплаты из ДДС и сохраняются в приложении только как `supplier_payment_match` к `cashflow_transaction`.
3. Месячная вкладка считает roll-forward по каждому поставщику.
4. `Свод` агрегирует:
   - расходы для ОПиУ;
   - положительные остатки как `Задолженность перед поставщиками`;
   - отрицательные остатки как `Выданные авансы поставщикам`.

Для прогнозирования оплат поставщикам платежный календарь использует УДКЗ/iiko unpaid supplies как primary signal для уже известных поставок и historical DDS cadence / rolling average как forecast signal для будущих поставок, суммы которых ещё неизвестны. Агентские сезонные корректировки допустимы, но должны иметь audit trail через `agent_run`, `source_reference` или manual owner-approved adjustment.

### Балансовое сопоставление

| Строка Баланса | Что даёт УДКЗ | Ограничение |
| --- | --- | --- |
| `Выданные авансы поставщикам` | `Свод` → секция `Дебиторка (авансы поставщикам) для Баланса`; источник по месяцам, статьям и `prepayment_type` | владелец 2026-05-27 решил: все префиксные остатки ведутся в УДКЗ; источники по типам требуют отдельного разбора |
| `Задолженность перед поставщиками` | `Свод` → секция `Кредиторка (поставщики) для Баланса`; исходно из месячных closing balances | master для Баланса = УДКЗ/manual roll-forward; iiko `План счетов -> Задолженность перед поставщиками` является source/control input по поставщикам сырья |
| `Расходы будущих периодов` | отдельной строки/вкладки нет | соответствует решению владельца 2026-05-24: РБП не выделяем в Балансе, всё префиксное идёт в авансы поставщикам |

### Префиксные категории из memory

| Тип | Есть ли в УДКЗ | Где видно |
| --- | --- | --- |
| `supplier_payment` / supplier-based advance | да | отрицательные остатки поставщиков в `Свод` → `Дебиторка (авансы поставщикам) для Баланса` |
| `rental_prepayment` | да | договор/ДДС/ручной source; УДКЗ агрегирует остаток как аванс поставщику |
| `subscription_prepayment` | да | contract/billing schedule и P&L accrual register; УДКЗ агрегирует остаток предоплаты |
| `ad_budget_balance` | да | остатки рекламных кабинетов через AI-агента или ручной ввод; УДКЗ хранит остаток как префиксный аванс |
| `tax_prepayment` | да, если появится | владелец 2026-05-25 подтвердил: налоговых предоплат сейчас нет; если появятся, тип ведется в УДКЗ |
| `phone_balance` | да | Mango/телефония через ЛК или ручной ввод; УДКЗ агрегирует как аванс поставщику |

## 7. MVP

### Что в первой итерации

1. Импорт структуры УДКЗ: `Контрагенты`, `Справочник`, `Регистрация вход. док-тов`, месячные roll-forward и `Свод` как read-only seed.
2. Manual opening register поставщиков на `2026-02-01`: поставщик, статья, сумма signed (`+` КЗ, `-` аванс), основание, источник, quality status, owner-review.
3. Прямая связь с DDS-модулем вместо `IMPORTRANGE`.
4. Карточка поставщика с текущим балансом: opening, документы, оплаты, closing.
5. Автоматическая выдача двух балансовых агрегатов на дату: `supplier_ap_balance` и `supplier_advance_balance`.
6. Разметка `prepayment_type` для отрицательных supplier-based остатков и внешних префиксных остатков, чтобы поддержать решение владельца о переносе РБП в авансы поставщикам внутри УДКЗ.
7. Контроль расхождений с iiko по продуктовым поставщикам.
8. Единый supplier dropdown из `counterparty` с ролью `supplier`, общий для УДКЗ, DDS, платежного календаря и balance views.

### За пределами MVP

- автоматическое чтение источников для рекламных кабинетов;
- автоматическое чтение налоговых переплат;
- автоматическое чтение Mango balance;
- owner loans / `owner_loan_register`;
- полноценный ЭДО-matching документов СБИС/DocsInbox.
