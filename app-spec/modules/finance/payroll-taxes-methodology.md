# Методология НДФЛ и страховых взносов по официальной занятости

Дата фиксации: 2026-05-31.
Статус: reconnaissance / owner review before implementation.

Документ фиксирует методологию для будущего продуктового расчета НДФЛ и страховых взносов по официально трудоустроенным сотрудникам. Это не кодовая спецификация миграции и не юридическая консультация: перед внедрением ставки, льготы и отчетные обязанности должны быть подтверждены налоговым агентом.

## A. Контекст

Бизнес уже ведет управленческий payroll и P&L, но полный контур налогов с зарплаты сейчас находится вне payroll-движка:

- в payroll-источниках есть удержание НДФЛ: в `Выгрузка` тип называется `НДФЛ Начислено`, в `Персональный отчет` колонка подписана как `Удержание НДФЛ`;
- это удержание уменьшает баланс сотрудника и не является выплатой сотруднику;
- строку P&L `Налоги с ЗП` нельзя считать только из зарплатной ведомости, потому что страховые взносы работодателя там не покрыты полностью;
- основной факт полной строки `Налоги с ЗП` сейчас берется из ДДС, статья `Налоги с З/п`; payroll используется как контроль.

Налоговый агент подтвержден в справочнике контрагентов как `CP-0021`; рабочий email: `askad02@mail.ru`. В этом документе не публикуются ФИО сотрудников, зарплаты из кадровых приказов и персональные реквизиты.

## C. НДФЛ

Роль бизнеса: ИП-работодатель является налоговым агентом по доходам сотрудников. Агентская обязанность: исчислить НДФЛ, удержать его из дохода сотрудника, перечислить в бюджет и сдать 6-НДФЛ.

Для будущего приложения базой НДФЛ должна быть не вся управленческая зарплата, а только официальный налогооблагаемый доход:

```text
official_taxable_income =
  official_salary
  + official_taxable_accruals
  - confirmed_tax_deductions
```

На текущий момент в repo нет подтвержденного набора `official_taxable_accruals` и нет документов по налоговым вычетам сотрудников. Поэтому MVP-формула должна начинаться с `official_salary`, а расширение на отпускные, больничные, премии, ГПХ и вычеты должно быть отдельным подтвержденным слоем.

Для налоговых резидентов РФ основная база, включая зарплату, с 2025 года облагается по прогрессивной шкале:

| Годовой доход по основной базе | Ставка |
| --- | ---: |
| до 2 400 000 руб. | 13% |
| 2 400 000 - 5 000 000 руб. | 15% с превышения |
| 5 000 000 - 20 000 000 руб. | 18% с превышения |
| 20 000 000 - 50 000 000 руб. | 20% с превышения |
| свыше 50 000 000 руб. | 22% с превышения |

Важно для модели: повышенная ставка применяется к превышению, а не ко всему доходу. Расчет должен идти нарастающим итогом с начала года по сотруднику и налоговому статусу. Если обычная официальная зарплата сотрудника не выводит его годовую базу выше 2,4 млн руб., фактическая ставка в простом MVP-сценарии будет 13%.

Сроки НДФЛ для налогового агента через ЕНС/ЕНП:

- удержано с 1-го по 22-е число месяца: уведомление до 25-го числа текущего месяца, уплата до 28-го числа текущего месяца;
- удержано с 23-го по последнее число месяца: уведомление до 3-го числа следующего месяца, уплата до 5-го числа следующего месяца;
- удержано с 23 по 31 декабря: уведомление и уплата до последнего рабочего дня года.

## D. Страховые взносы работодателя

Страховые взносы работодателя не являются удержанием сотрудника и не должны уменьшать `total_payable`. Это расход/обязательство работодателя, который должен попадать в tax payroll burden и сверяться с ДДС/налоговым агентом.

Базовая федеральная рамка на 2026 год:

- единая предельная база страховых взносов: 2 979 000 руб. на физическое лицо за год;
- общий единый тариф: 30% в пределах базы, 15,1% сверх базы;
- срок уплаты страховых взносов через ФНС: не позднее 28-го числа следующего месяца;
- расчетный период - календарный год, отчетные периоды - 1 квартал, полугодие, 9 месяцев, год.

Пониженный тариф МСП в 2026 году нельзя hardcode'ить как "15% выше МРОТ". По официальной публикации ФНС с 2026 года 15% применяется к выплатам, превышающим 1,5 МРОТ, и только для субъектов МСП в приоритетных сферах при одновременном выполнении условий:

- соответствующий вид деятельности указан основным в ЕГРЮЛ/ЕГРИП;
- доля доходов от основного вида деятельности не ниже 70%.

Федеральный МРОТ с 2026-01-01: 27 093 руб. Значит порог 1,5 МРОТ:

```text
msp_monthly_threshold_2026 = 27 093 * 1.5 = 40 639.50 руб.
```

Предварительная формула для qualifying SME:

```text
standard_part = min(official_contribution_base_month, 40_639.50)
reduced_part = max(official_contribution_base_month - 40_639.50, 0)

employer_social_contributions =
  standard_part * 30%
  + reduced_part * 15%
```

Если право на МСП-тариф не подтверждено налоговым агентом, применять общий тариф:

```text
within_annual_limit =
  min(ytd_base_before + period_base, 2_979_000)
  - min(ytd_base_before, 2_979_000)

above_annual_limit =
  period_base - within_annual_limit

employer_social_contributions =
  within_annual_limit * 30%
  + above_annual_limit * 15.1%
```

Травматизм идет отдельно через СФР. По source map письма `#837` текущий рабочий признак: ставка 0,2%. Ее нельзя считать универсальной без подтверждения класса профессионального риска / уведомления СФР.

Предварительная формула травматизма:

```text
injury_contribution = official_injury_base_month * injury_rate
```

При подтвержденной ставке из текущих писем:

```text
injury_rate = 0.2%
```

Срок уплаты травматизма: ежемесячно не позднее 15-го числа месяца, следующего за месяцем начисления. Отчетность по травматизму подается в составе ЕФС-1, раздел 2, ежеквартально не позднее 25-го числа месяца после отчетного периода.

## F. Текущее состояние кода

Кодовая база не содержит полноценного расчета НДФЛ и страховых взносов:

- `apps/api/app/services/payroll_calculator.py`: `PAYROLL_SETTING_KEYS` не содержит `payroll.tax_rates`; расчет строки формирует base/premium/percent, затем manual deduction и deposit withholding. НДФЛ и employer contributions не считаются.
- `apps/api/app/models/payroll.py`: `PayrollLine` содержит `base_pay`, `premium`, `percent_pay`, `fund_accrual`, `deduction`, `total_payable`, `components`; отдельных полей `ndfl_deduction` и `employer_social_contributions` нет.
- `apps/api/app/schemas/payroll.py`: `PayrollLineRead` уже имеет `ndfl_deduction: float = 0`, но это только schema placeholder.
- `apps/api/app/api/v1/routes/payroll.py`: `serialize_payroll_line` выставляет `ndfl_deduction` в `0`.
- `apps/api/app/models/employee.py` и `apps/api/app/schemas/employees.py`: нет `is_official_employment` и `official_salary`.
- `PayrollDeductionCategory` ограничен типами `fine`, `withholding`, `deposit_writeoff`; налоговый тип в текущей модели не выделен.

Вывод: следующий implementation prompt должен добавить данные официальной занятости, настройку ставок и вычисляемые/хранимые налоговые поля. В этом проходе код, модели и миграции не менялись.

## G. Базовые формулы для будущего продукта

### G1. НДФЛ сотрудника

```text
official_taxable_base_month =
  official_salary
  + official_taxable_accruals
  - confirmed_tax_deductions

ndfl_ytd_before = tax_by_progressive_scale(ytd_taxable_base_before)
ndfl_ytd_after = tax_by_progressive_scale(ytd_taxable_base_before + official_taxable_base_month)

ndfl_deduction_month = ndfl_ytd_after - ndfl_ytd_before
```

Простой MVP для резидента без вычетов и без превышения 2,4 млн руб.:

```text
ndfl_deduction_month = official_salary * 13%
```

В payroll line:

```text
total_before_tax_and_deductions =
  base_pay + premium + percent_pay + other_accruals

employee_total_payable =
  total_before_tax_and_deductions
  - ndfl_deduction_month
  - manual_deductions
  - deposit_withholding
```

### G2. Взносы работодателя

Общий тариф, если льгота не подтверждена:

```text
employer_contributions =
  within_annual_limit * 30%
  + above_annual_limit * 15.1%
```

МСП-тариф 2026 при подтвержденном праве:

```text
employer_contributions =
  min(period_base, 40_639.50) * 30%
  + max(period_base - 40_639.50, 0) * 15%
```

Травматизм:

```text
injury_contribution = injury_base * injury_rate
```

Итоговая налоговая нагрузка по официальной зарплате:

```text
payroll_tax_burden =
  ndfl_deduction_month
  + employer_contributions
  + injury_contribution
```

Важно: `ndfl_deduction_month` удерживается из дохода сотрудника, а `employer_contributions` и `injury_contribution` оплачиваются работодателем сверх зарплаты.
