# Курьеры — депозиты (MVP методология)

Дата фиксации: 2026-06-04.
Статус: утверждено владельцем.
Связано: `app-spec/modules/couriers/kpi-methodology.md`, `app-spec/modules/couriers/admin-evaluations.md`.

## 1. Скоуп MVP

Депозиты курьеров — самостоятельная сущность в модуле «Курьеры», **не часть общего Payroll** (Payroll-модуль управляет депозитами производственного персонала и кассиров).

В MVP:

- Настройки (цели и ставки удержаний)
- Список курьеров с начальными балансами и текущим балансом
- Ручной ввод операций: **Пополнение / Возврат / Списание**
- Просмотр истории операций по курьеру

Вне MVP:

- Автоматический ежедневный сбор 500/200 ₽ за смену (планируется через спецсчёт в iiko)
- Post-shift checklist «собрал ли депозит?» (отложен)
- Удержания за порчу / штраф / недостачу (отложено)
- Telegram-бот (отложен)
- «Гарантфонд» 47 200 ₽ — устаревшая модель, не моделируется

## 2. Параметры

| Параметр | Значение по умолчанию | Где редактируется |
| --- | --- | --- |
| Целевой депозит | 5 000 ₽ | Исходные данные → Депозиты → Курьеры |
| Удержание за смену primary | 500 ₽ | там же, отдельное поле |
| Удержание за смену secondary | 200 ₽ | там же, отдельное поле |
| Автоматическое удержание | выключено | тумблер, в MVP всегда off |

Значения параметров общие для всех курьеров (нет индивидуальных целей).

## 3. Начальные балансы

Источник: текущая Google Sheets книга владельца + ручное уточнение по курьерам с частичным остатком.

Правила:

- Каждый сотрудник с `position = Курьер` автоматически попадает в список депозитов.
- На странице вводятся два поля: **дата открытия счёта** + **opening_balance** (сумма на эту дату).
- Если курьер активен и opening_balance < target — баланс будет дособираться через операции `Пополнение`.
- Если курьер уже уволен и с положительным балансом — сверяем вне приложения, импортируем как остаточный, потом одной операцией `Возврат` или `Списание` обнуляем.

## 4. Типы операций

В MVP — три типа:

| Тип | Знак | Когда применяется | Влияние на баланс |
| --- | --- | --- | --- |
| `Пополнение` | + | ручной ввод админом или менеджером (импорт сборов из Sheets, корректировки) | увеличивает |
| `Возврат` | − | при увольнении, если менеджер принял решение «выплатить» | уменьшает; в учёте — выплата курьеру |
| `Списание` | − | при увольнении, если менеджер принял решение «не выплачивать» (forfeit); деньги уходят в прибыль вне приложения | уменьшает |

Решение «Возврат / Списание» принимает менеджер (как сейчас работает с производственным персоналом).

Каждая операция хранит: дата, сумма, тип, комментарий (опц.), автор, created_at.

## 5. Расчёт баланса

```
current_balance(courier) =
    opening_balance
  + sum(amount where type = 'Пополнение')
  − sum(amount where type in ('Возврат', 'Списание'))
```

Дополнительные показатели для UI:

- `% достижения цели` = `current_balance / target * 100%`, ограничивается 100%.
- `остаток до цели` = `max(target − current_balance, 0)`.

## 6. UI

### 6.1. Настройки — Исходные данные → Депозиты → Курьеры

По образу существующей вкладки производственного персонала, плюс отдельная подвкладка «Курьеры».

Структура подвкладки:

- Карточки KPI вверху (по аналогии с производственным): курьеров с включённым удержанием, сумма всех балансов, средний % достижения цели, исключённые из удержания.
- Блок «Общие правила удержания»: целевой депозит, удержание primary, удержание secondary. Тумблер автоматического удержания (в MVP всегда off, заблокирован с подсказкой «Появится при подключении iiko спецсчёта»).
- Блок «Начальные балансы»: таблица всех 22 (и далее) курьеров. Колонки: курьер, дата, opening_balance. Редактируется inline, изменения с audit.

### 6.2. Депозиты курьеров — отдельная страница в разделе «Курьеры»

Назначение: оперативная работа менеджера / админа.

Структура:

- Список курьеров с current_balance, % достижения, последняя операция.
- Фильтры: активные / уволенные, primary / secondary, цвет «не добрал».
- Действия на строке: «+ Пополнение», «+ Возврат», «+ Списание», «История операций».
- Карточка курьера: opening_balance + полная история операций с автором и комментарием.

Mobile-friendly не обязателен (это не для админа на смене), для desktop менеджера.

## 7. Аудит и контроль

- Каждая операция и каждое изменение opening_balance логируется: автор, время, старое/новое значение.
- Удаление операций — запрещено. Корректировка — через новую обратную операцию с комментарием.
- Изменение `opening_balance` после первой операции — только менеджером, с комментарием.

## 8. Связь с другими модулями

- Сущность `employee` (position = Курьер) — источник списка курьеров.
- Категория primary/secondary — источник правила удержания (которое будет применяться при автоматизации).
- Payroll-модуль НЕ читает и НЕ пишет депозиты курьеров. Граница строгая.
- Будущий iiko спецсчёт станет источником `Пополнение` операций (через интеграционный job), но это вне MVP.
