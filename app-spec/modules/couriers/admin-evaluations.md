# Курьеры — оценки админов (MVP методология)

Дата фиксации: 2026-06-04.
Статус: утверждено владельцем.
Связано: `app-spec/modules/couriers/kpi-methodology.md`, `app-spec/modules/couriers/deposits.md`.

## 1. Скоуп MVP

Оценки админов — управленческий журнал «отличий» курьера. Не KPI и не вход в payroll. Информативно показывают, как курьер работает в текущем месяце.

В MVP:

- Справочник из 14 утверждённых критериев с фиксированными баллами.
- Журнал оценок: курьер, критерий, дата, комментарий (опц.), автор.
- Несколько оценок в день одному курьеру разрешено.
- Автор может редактировать или удалить свою оценку **в течение 30 минут** после создания.
- Месячная агрегация по курьеру.
- Веб UI mobile-friendly (архитектура готова к подключению Telegram-бота позже).
- Курьеры свои оценки в MVP не видят.

Вне MVP:

- Добавление новых критериев (отложено)
- Привязка оценки к конкретной смене курьера (отложено)
- Влияние оценок на бонусы / статус primary-secondary / график
- Личный кабинет курьера со своими оценками
- Telegram-бот для admin'ов
- Post-shift checklist (объединяющий оценку, причину досрочного закрытия и фиксацию сбора депозита)

## 2. Кто оценивает

**Автор оценки** — сотрудник с одновременно:

- `position = Кассир`
- `payroll_role = admin`

(Эти сущности уже есть в БД.)

Других ролей в MVP допускать к оценке нельзя. Менеджер и владелец могут только просматривать.

## 3. Справочник критериев

Источник: текущая Google Sheets книга владельца.

| Код | Критерий | Балл |
| --- | --- | ---: |
| `praise_from_client` | Похвала от клиента | +7 |
| `fast` | Быстрый | +5 |
| `responsible` | Ответственный | +3 |
| `pleasant_work` | Приятно работать | +1 |
| `conflict` | Конфликт | 0 |
| `no_distinctions` | Без отличий | 0 |
| `missed_comments` | Не видет комменты | −1 |
| `no_change_taken` | Не взял сдачу | −1 |
| `slow_response` | Долгий отклик | −2 |
| `broke_down` | Сломался | −2 |
| `unreachable` | Не выходит на связь | −3 |
| `no_route` | Отсутствие маршрута | −3 |
| `slow` | Медленный | −5 |
| `overturned_order` | Перевернул заказ | −7 |

Бизнес-логика спорных критериев (зафиксировано владельцем):

- **Конфликт = 0**: фиксируем сам факт конфликта без оценки виноватого.
- **Без отличий = 0**: маркер того, что админ работал с курьером и просто не было повода ни за что хвалить или порицать. Отличается от «забыли оценить» (когда записи вообще нет).
- **Сломался = −2**: не всегда вина курьера, но курьеры регулярно используют поломку как отговорку. Небольшой минус как сдерживающий фактор.

Изменение справочника (добавление критериев, корректировка баллов) — через настройки приложения с audit, доступно только владельцу / менеджеру (не админу).

## 4. Сущности

### `courier_evaluation_criterion`

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | int | PK |
| `code` | string | технический код (см. таблицу §3) |
| `label` | string | отображение |
| `score` | int | балл |
| `is_active` | bool | можно ли использовать в новых оценках |
| `display_order` | int | порядок в UI |

Сидируется при миграции 14 значениями.

### `courier_evaluation`

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | int | PK |
| `courier_employee_id` | FK employee | оцениваемый курьер |
| `criterion_id` | FK criterion | критерий |
| `score_snapshot` | int | копия балла на момент создания (на случай изменения справочника позже) |
| `comment` | text | опционально |
| `evaluated_at` | date | дата эпизода (по умолчанию — сегодня; админ может поставить вчера, не дальше) |
| `created_by` | FK employee | автор-админ |
| `created_at` | timestamp | время создания |
| `updated_at` | timestamp | время последнего изменения |
| `deleted_at` | timestamp NULL | soft-delete если автор удалил в окно 30 мин |

Несколько оценок на одного курьера в один день — разрешены, никаких unique constraint по `(courier, date)`.

## 5. Правила редактирования

- Автор может **изменить критерий и комментарий** своей оценки в течение **30 минут** после `created_at`. После — нельзя.
- Автор может **удалить** свою оценку в течение тех же 30 минут (soft-delete с `deleted_at`).
- Менеджер / владелец редактировать чужие оценки не могут (это управленческий журнал админа, не финансовый документ).
- Если нужно отменить старую оценку — допустимо поставить новую противоположную и оставить старую (для прозрачности).

## 6. Канал ввода

### MVP — веб-страница, mobile-friendly

Маршрут (черновик): `/couriers/evaluations`. Также кнопка-быстрого-доступа «+ Отличие» в разделе «Курьеры».

Форма:

1. Курьер (dropdown активных курьеров)
2. Критерий (dropdown из 14, сгруппирован визуально: позитив / нейтрал / негатив)
3. Комментарий (опционально)
4. Дата (по умолчанию сегодня, можно вчера)
5. Submit → toast «Отличие зафиксировано», в течение 30 мин показывается кнопка «Изменить / Удалить» на собственных оценках

Список последних оценок (для контекста): автор видит свои за сегодня + общую ленту последних 20.

### Архитектура под бот

Тот же endpoint API должен принимать оценки и от Telegram-бота. В сущности `courier_evaluation` поле `source` (`web` / `telegram` / `api`) для аналитики канала. Авторизация бота — отдельным механизмом (связка telegram chat_id с employee), не в скоупе MVP.

## 7. Агрегация и статистика

Только **месячные** агрегаты, по запросу.

Метрики по курьеру за месяц:

- `score_sum` — сумма баллов
- `positive_count` — количество строк с `score > 0`
- `negative_count` — количество строк с `score < 0`
- `neutral_count` — количество строк с `score == 0`
- `top_criteria` — 3 самых частых критерия

Также общая лента: «последние оценки» с фильтром по курьеру / админу / критерию / месяцу.

Где показывается:

- В разделе «Курьеры → Статистика» — карточка по каждому активному курьеру с месячным `score_sum` и top критериями.
- В карточке курьера — история оценок и месячные агрегаты.

## 8. Связь с другими сущностями

- `employee` (position = Курьер) — оцениваемый.
- `employee` (position = Кассир + payroll_role = admin) — автор.
- KPI MVP (`kpi-methodology.md`) — оценки **не входят** в KPI, отображаются параллельно как отдельная панель.
- Депозиты (`deposits.md`) — нет прямой связи.
