# Курьеры — смена и оценки (объединённая страница)

Дата фиксации: 2026-06-14.
Статус: утверждено владельцем (итерации по HTML-макапу).
Связано: `app-spec/modules/couriers/deposits.md`, `app-spec/modules/couriers/admin-evaluations.md`.

## 1. Идея

Пункты сайдбара «Депозиты» и «Оценки» объединяются в один раздел **«Смена»** (`/couriers/shift`) с тремя вкладками-инбоксами:

1. **На смене** (основной инбокс) — оперативная обработка курьеров текущего дня: оценка + депозит + подтверждение смены.
2. **Депозиты** — агрегатная таблица балансов (прежняя страница депозитов) с новой сортировкой и блокировкой операций у собравших.
3. **Оценки** — журнал всех оценок (прежняя страница оценок) + ручное добавление.

Старые маршруты `/couriers/deposits` и `/couriers/evaluations` редиректят на соответствующие вкладки. «Статистика» и «График» остаются отдельными пунктами сайдбара — не трогаются.

Права: новый пункт виден при наличии `couriers.deposits.read` **или** `couriers.evaluations.read`. Новых permission-кодов не вводим — переиспользуем существующие.

## 2. Вкладка «На смене» (основной инбокс)

### Состав смены за день

Курьеры, **открывшие смену в выбранный день** (по локальной дате `opened_at`, MSK), и открытые, и закрытые смены. Источник — `courier_iiko_shift`, сгруппированный по `employee_id`. По умолчанию день = сегодня; есть навигация по датам (← →).

Курьеры с открытой сменой в iiko, **не сопоставленные** со штатом (`employee_id IS NULL`), показываются отдельным предупреждающим блоком «не сопоставлены» — их нельзя обрабатывать (сначала сопоставить в «Штате»), и в гейтинг подтверждения они **не входят**.

Категория (основной/доп) показывается из матча смены (`courier_shift_match`), **read-only** — назначается в «Графике», здесь не редактируется.

### Действия по каждому курьеру

- **Оценить** — открывает модальное окно по центру с 14 критериями. Сохранение создаёт `courier_evaluation` за этот день. Кнопка активна только когда день = сегодня/вчера (ограничение `_validate_evaluated_at`); для более старых дней оценку закрывают тоглом «Не оценивать».
  - **«Без отличий» (score 0) убран из модалки** — его роль выполняет тогл «Не оценивать».
- **Депозит** — открывает диалог операции (Пополнение / Возврат / Списание), `transaction_date` = день инбокса. Кнопка **неактивна**, если депозит уже **собран** (`remaining_to_target == 0`) или включён тогл «Не собирать депозит».
- **Тогл «Не оценивать»** — снимает требование оценки. Доступен, пока оценки за день нет.
- **Тогл «Не собирать депозит»** — снимает требование депозита; при включении **обязательно** открывается окно с комментарием (почему не собираем). Доступен, пока депозит не собран и операции за день нет.

### Готовность курьера

```
eval_ok    = есть оценка за день  OR  тогл «не оценивать»
deposit_ok = депозит собран (remaining==0)  OR  есть операция за день  OR  тогл «не собирать депозит»
ready      = eval_ok AND deposit_ok
```

Несохранённые (не готовые) строки подсвечены; показывается сводка «Готово N из M».

### Подтверждение смены — одна кнопка на весь день

- Кнопка **«Сохранить смену»** вверху (одна на день, не на строку). **Активна только когда `ready` у всех курьеров состава** (`can_confirm`). Иначе disabled с подсказкой, сколько осталось.
- Нажатие → день переходит в статус `confirmed` (`courier_shift_day`), фиксируются `confirmed_by` / `confirmed_at`.
- После подтверждения день read-only (кнопки оценки/депозита/тоглов заблокированы), кнопка превращается в **«Откатить смену»** (идемпотентно) — возврат в `draft` для правок.

## 3. Вкладка «Депозиты»

Прежняя таблица балансов. Новое:

- **Сортировка тремя группами** (вместо алфавита):
  1. *Собирают* (`0 < balance < target`) — по убыванию баланса (больше собрал — выше);
  2. *Собрали полностью* (`balance >= target`);
  3. *Без операций* (`balance == 0` и нет транзакций) — внизу.
- Кнопка **«Операция» неактивна** у тех, кто собрал полностью (собирать нечего).

## 4. Вкладка «Оценки»

Прежний журнал оценок без изменений логики: фильтры, лента, добавление, окно редактирования 30 мин.

## 5. Модель данных

### `courier_shift_day` — подтверждение дня (одна запись на дату)

| Поле | Тип | Примечание |
| --- | --- | --- |
| `work_date` | date PK | день смены (локальный MSK) |
| `status` | enum `courier_shift_day_status` (`draft`/`confirmed`) | default `draft` |
| `confirmed_by` | uuid FK user, null | кто подтвердил |
| `confirmed_at` | timestamptz, null | когда подтвердил |
| `created_at`/`updated_at` | timestamptz | |

### `courier_shift_review` — обработка курьера за день (тоглы)

| Поле | Тип | Примечание |
| --- | --- | --- |
| `work_date` + `courier_employee_id` | составной PK | |
| `eval_skipped` | bool default false | тогл «не оценивать» |
| `deposit_skipped` | bool default false | тогл «не собирать депозит» |
| `deposit_skip_comment` | text, null | обязателен при `deposit_skipped=true` (app-level) |
| `updated_by` | uuid FK user, null | |
| `created_at`/`updated_at` | timestamptz | |

`eval_present` / `deposit_present` **не хранятся** — вычисляются по `courier_evaluation` (evaluated_at = день) и `courier_deposit_transaction` (transaction_date = день).

Миграция: `0104_courier_shift_day` (down_revision `0103_auxiliary_create_permission`).

## 6. API

- `GET /couriers/shift-day?date=YYYY-MM-DD` → статус дня + список курьеров с готовностью + несопоставленные + сводка `can_confirm`.
- `PUT /couriers/shift-day/{work_date}/courier/{employee_id}/review` → `{eval_skipped?, deposit_skipped?, deposit_skip_comment?}` (валидация: skip депозита требует комментарий).
- `POST /couriers/shift-day/{work_date}/confirm` → 400, если не все `ready`.
- `POST /couriers/shift-day/{work_date}/unconfirm` → возврат в `draft`.

Оценки и депозиты ставятся существующими эндпоинтами (`POST /couriers/evaluations`, `POST /couriers/{id}/deposit/transactions`). Права записи: `couriers.deposits.edit` или `couriers.evaluations.edit`.
