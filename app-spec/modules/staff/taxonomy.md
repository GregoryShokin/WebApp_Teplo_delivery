# Таксономия сотрудников: должности, роли, категории, надбавки

Канонический источник истины по структуре сотрудников в приложении. Зафиксирован владельцем 2026-05-29. Любые изменения в моделях БД, формах Штата, payroll-конфигурации и iiko-синхронизации должны сверяться с этим документом.

## Четыре сущности

Внутри приложения существуют четыре разные сущности. **Не смешивать.**

| # | Сущность | Что это | Кто задаёт |
|---|---|---|---|
| 1 | **Должность** (position) | Формальная роль сотрудника в iiko. Тянется при синхронизации. | iiko |
| 2 | **Роль** (specialization) | Функциональная специализация внутри должности; влияет на расчёт зарплаты. | Приложение (Штат) |
| 3 | **Категория** (category) | Уровень внутри роли; влияет на ставку. | Приложение (Штат) |
| 4 | **Надбавки** (premiums) | Флаги/доплаты сверх базовой ставки (Старший, Зам старшего, надбавка пт/сб и т.д.). | Приложение (Штат + Настройки) |

В iiko понятие «роль» (role) означает то, что у нас называется «должность» (position). Это терминологическая накладка — учитывать при чтении iiko-кода и API.

## Должности — 8 позиций

| Должность | Источник | Комментарий |
|---|---|---|
| Кассир | iiko | Только обычный кассир. |
| Повар | iiko | |
| Управляющий | iiko | |
| Системный администратор | iiko | Подтягивается при синке; **не создаётся** из формы приложения (заводится IT вручную в iiko). |
| Курьер | iiko (через отдельный Python-сервис iikoCloud) | |
| Менеджер | iiko | |
| Уборщица | iiko | Вспомогательный персонал; подтягивается при синке, **не создаётся** из формы приложения. |
| Посудомойка | iiko | Вспомогательный персонал; маппится из iiko-должности «Посудомойка» как есть, **не создаётся** из формы приложения. |

**Исключения при маппинге из iiko:**
- iiko-должность «Кассир-фастфуда» в приложение **не маппится**: не показывается в Штате, не попадает в расчёты, не создаётся при синке. Если такая запись приходит — пропускать (или помечать `requires_setup` и скрывать из основных потоков, окончательное поведение — в реализации).
- Все остальные iiko-должности, не входящие в список 8 выше (Бармен, Официант, Охранник, Финансовый директор, Шеф-повар и пр.), — в приложение не маппятся.

### Вспомогательный персонал

`Уборщица` и `Посудомойка` — канонические должности без payroll-ролей:

- ролей нет;
- категорий нет;
- надбавки `Старший` / `Зам старшего` неприменимы;
- ПИН-код для открытия смены не обязателен;
- карточка с ФИО и одной из этих должностей считается валидной и получает статус `active`;
- через форму создания в приложении не создаются, но при синхронизации из iiko подтягиваются и отображаются.

## Роли — специализации внутри должности

Роли есть только у двух должностей. У остальных поле «роль» в UI скрыто.

| Должность | Доступные роли |
|---|---|
| Кассир | Администратор |
| Повар | Сушист, Пиццерист, Шаурмист, Заготовщик |
| Управляющий | — |
| Системный администратор | — |
| Курьер | — |
| Менеджер | — |
| Уборщица | — |
| Посудомойка | — |

## Категории — уровни внутри роли

Категории есть только у некоторых ролей. У остальных поле «категория» в UI скрыто.

| Роль | Доступные категории |
|---|---|
| Администратор (Кассир) | 2, 3, 4, стажёр |
| Сушист (Повар) | 1, 2, 3, стажёр |
| Пиццерист (Повар) | 1, 2, 3, стажёр |
| Шаурмист (Повар) | 3, 4, стажёр |
| Заготовщик (Повар) | 3 |
| — (Управляющий, Системный администратор, Курьер, Менеджер, Уборщица, Посудомойка) | — |

Категория «стажёр» — отдельный уровень, не считается обычным числовым. У Заготовщика категория одна — «3», стажёра нет.

## Многоролевость

Сотрудник может иметь несколько ролей одновременно (повар, умеющий быть и сушистом, и пиццеристом). Каждая назначенная роль имеет свою категорию. Одна из ролей помечается как **основная** — используется по умолчанию в графиках/сменах/расчётах.

Дополнительные роли (вторая, третья и т.д.) необязательны. Категория обязательна только для основной роли и для каждой добавленной дополнительной роли (если у этой роли есть категории).

## Надбавки

- **Старший** — флаг в карточке. Необязательный.
- **Зам старшего** — флаг в карточке. Необязательный.
- **Надбавка пт/сб** — глобальная настройка, не флаг карточки. Правила начисления см. в [Payroll](../finance/payroll.md).

### Применимость флагов «Старший» и «Зам старшего»

| Должность | Старший | Зам старшего |
|---|---|---|
| Кассир (= Администратор) | да | да |
| Повар (любая роль) | да | да |
| Курьер | да | **нет** |
| Управляющий | нет | нет |
| Системный администратор | нет | нет |
| Менеджер | нет | нет |
| Уборщица | нет | нет |
| Посудомойка | нет | нет |

Флаги хранятся на уровне сотрудника (Employee), не на уровне отдельной роли. UI должен скрывать чекбоксы у тех должностей, где они не применимы.

## Применение в UI карточки сотрудника

Форма создания/редактирования сотрудника на странице «Штат» должна строиться каскадом:

1. **ФИО** — обязательное.
2. **Должность** — селектор. При создании показываются только 5 опций: Кассир, Менеджер, Повар, Управляющий, Курьер (Системный администратор, Уборщица и Посудомойка не создаются из приложения). При редактировании показывается фактическая должность.
3. **Основная роль** — появляется только если у выбранной должности есть роли. Селектор с допустимыми ролями. Обязательная.
4. **Категория основной роли** — появляется только если у выбранной роли есть категории. Селектор с допустимыми категориями. Обязательная (когда поле видимо).
5. **Дополнительные роли** — кнопка «Добавить роль». Можно добавить несколько; для каждой — своя категория (если у роли есть категории). Необязательно.
6. **Старший** / **Зам старшего** — чекбоксы. Необязательно.
7. **ПИН-код для открытия смены** — обязательное для Кассира, Повара, Управляющего, Системного администратора, Курьера и Менеджера. Для Уборщицы и Посудомойки не обязателен и не влияет на статус. Когда поле используется — ровно 4 цифры.

Все опции селектов рендерятся из этой таксономии, чтобы нельзя было сохранить невалидную комбинацию (должность без роли там где роль обязательна, роль из чужой должности, категория не из набора роли и т.п.).

## Невалидные карточки

Если из iiko прилетает сотрудник с должностью «Кассир-фастфуда» или с любой должностью не из 8 канонических — **не маппится в приложение вообще**. Если такая запись уже есть в локальной БД (исторически синканная) — **удалить** вместе со связанными записями (assignments, attendance, ledger). По решению владельца таких сотрудников в системе быть не должно.

Если из iiko прилетает сотрудник с одной из 8 канонических должностей, но без роли/категории/ПИН там, где они обязательны, — статус `requires_setup`, показывается в Штате с пометкой «Требует проверки», пока менеджер не дозаполнит обязательные поля.

Для Уборщицы и Посудомойки роль, категория и ПИН не обязательны: карточка с ФИО и канонической должностью сразу считается валидной (`active`), если сотрудник не удалён/не уволен.
