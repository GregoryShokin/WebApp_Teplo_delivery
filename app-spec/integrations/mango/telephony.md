# Работа с телефонией

Дата фиксации: 2026-05-20.

## Назначение

Этот документ — единая точка по всему, что связано с телефонией в проекте «Тепло»:

- финансовая сторона: как закрывать строку P&L `Телекоммуникации`;
- технический контур: как работать со звонками, записями разговоров и транскриптами через публичный API Mango Office;
- управление хранилищем записей;
- метрики, которые телефония даёт для управленческой панели.

Поставщик: **Mango Office (Манго Телеком)**, плюс фиксированные сопутствующие компоненты — `iHC.ru` (сервер кастомных программ, 600 ₽/мес) и `Микроэл` (интернет, 3 230 ₽/мес).

## Два независимых контура Mango

Важно с самого начала: у Mango есть **два разных API-контура**, которые путать нельзя.

| Контур | Назначение | Авторизация | Документация | Статус в проекте |
| --- | --- | --- | --- | --- |
| **LK / Финансы** | Дашборд `Расходы на продукты`, биллинг, договоры, тарифы | OIDC SSO + Yandex SmartCaptcha + альтернативный MFA по email/SMS. Используется логин владельца | Приватная, восстановлена из SPA-бандлов | Headless заблокирован на CAPTCHA. См. варианты ниже |
| **VPBX API** | История звонков, записи разговоров, сотрудники, обратные звонки, SMS, события | HMAC SHA256 на `api_key` + `api_salt`, выпускаемых в ЛК → «Интеграции». Логин/пароль владельца не нужен | Публичная: [mango-office.ru/support/integratsiya-api](https://www.mango-office.ru/support/integratsiya-api/) | Не подключен; ключи не выпущены |
| **Speech Analytics API** | Транскрипты разговоров, тематика, ключевые слова, оценка эмоций | Отдельный токен в ЛК → «Коллтрекинг → Настройки → API» | Публичная: [products/.../speech-analytics](https://www.mango-office.ru/products/virtualnaya_ats/vozmozhnosti/speech-analytics/) | Не подключен; статус подключения сервиса у владельца неизвестен |

## 1. Финансовая строка `Телекоммуникации`

### Состав

Подтверждено владельцем 2026-05-19:

```text
Телекоммуникации =
    Mango Office телефония за предыдущий месяц (переменная)
  + iHC.ru сервер 600 руб.
  + Микроэл интернет 3 230 руб.
```

iHC.ru и Микроэл — фиксированные суммы по договору. Mango — переменная компонента, верхний итог `Мой продуктовый набор №1` в дашборде `Расходы на продукты`. Контрольный пример: апрель 2026 → `10 189,52 ₽`.

Подробное правило строки и обоснование — в [pnl-build-methodology.md](/business-docs/finance/pnl-methodology.md), раздел «2026-05-19. Телекоммуникации».

### Почему сложно автоматизировать

LK Mango Office защищён двойным барьером:

1. **Angular SPA** для логина — HTML-формы нет, без браузера разобрать нельзя.
2. **Yandex SmartCaptcha** обязательная на `POST /sso/oidc/auth/vpbx` (параметр `captcha_token`). Альтернативные пути входа (`request-otp`, `2fa-code`) требуют OTP-кода из email или SMS.

Endpoint'ы самого отчёта найдены и поняты (`POST /product-expenses/report-{request,status,result,export}` — async паттерн `request → poll → result`, ответ содержит `html_table` для парсинга). Но без рабочей session cookie они не дёргаются.

Артефакты headless-попытки сохранены в репозитории:

- `research/scripts/mango/export_telecom.py` — идемпотентный скрипт с resume через `research/private/mango/session.json`.
- `research/scripts/mango/endpoint_map.md` — карта endpoint'ов LK.
- `research/private/mango/raw/01_lk_root..04_vpbx_login` — снимки шагов OIDC с маскированными секретами.
- `research/private/mango/raw/spa/` — Angular-бандлы для будущего discovery.

### Открытые варианты автосбора

| # | Путь | Усилие владельца | Усилие проекта | Срок жизни решения |
| --- | --- | --- | --- | --- |
| A | Импорт cookies из браузера в `research/private/mango/session.json` после ручного логина со SmartCaptcha | Залогиниться + экспортировать cookies через Chrome extension типа Cookie-Editor | Скрипт `export_telecom.py` уже умеет resume через session.json | Cookie протухает за дни-недели; повторный экспорт ~30 сек |
| B | Ручной CSV-экспорт из дашборда | Залогиниться, выбрать 6 периодов, нажать «Экспорт», прислать CSV | Парсер CSV → processed | Разовое решение, ежемесячно повторять |
| C | Headed Playwright с интерактивной CAPTCHA | Установить Playwright Chromium, владелец вручную решает SmartCaptcha при запуске | Сценарий и оркестрация | Каждый месяц интерактивно |
| D | Email — Mango высылает счета/УПД | Подтвердить, что счета приходят на email или в СБИС/DocsInbox | Парсер email/PDF либо подтягивание через СБИС API | Стабильно, как только инвойсы найдены |
| E | Скип — фиксированная сумма | — | Закрыть строку как `Mango ≈ 10 000 + iHC 600 + Микроэл 3 230 = 13 830 руб./мес.`, раз в квартал ручная сверка | Точность ~95%, потеря ~720 руб./мес. |

Текущее решение: путь не выбран, строка остаётся в статусе `требует проверки` для месяцев 2025-11 — 2026-04 до решения владельца.

## 2. VPBX API: работа со звонками и записями

### Авторизация

Совершенно другой контур, не пересекается с финансовым.

- Никакой OIDC и SmartCaptcha.
- `api_key` и `api_salt` выпускаются один раз в ЛК Mango → «Интеграции».
- Подпись запроса: `sign = sha256(api_key + json_body + api_salt)`. Передаётся в body или заголовке вместе с `api_key` и `json`.
- Рекомендуется выпустить отдельный технический аккаунт, не привязанный к личному пользователю владельца.

### Endpoint'ы

Базовый URL: `https://app.mango-office.ru`.

| Endpoint | Метод | Назначение |
| --- | --- | --- |
| `/vpbx/stats/request` | POST | Заказать отчёт по истории звонков за период (async). Возвращает `request_id` |
| `/vpbx/stats/result` | POST | Забрать готовый отчёт по `request_id`. Дата, длительность, направление, номера, сотрудник, причина завершения |
| `/vpbx/queries/recording/post/` | POST | Скачать запись разговора по `recording_id`. Параметр `action=download` либо `action=get_url` (ссылка с TTL по `json.expires`) |
| `/vpbx/commands/callback` | POST | Заказать обратный/исходящий звонок |
| `/vpbx/commands/callback_group` | POST | Групповой звонок |
| `/vpbx/commands/sms` | POST | Отправить SMS |
| `/vpbx/config/users/request` | POST | Список сотрудников и их добавочных номеров |

Webhook «Конец звонка» — Mango может пушить событие завершения звонка с метаданными на наш callback URL. Настраивается в ЛК.

### Что можно сделать через API

- Получить полную историю звонков за любой период.
- Скачать любые записи разговоров (mp3/wav) и архивировать локально.
- Получить ссылки на записи с TTL для встраивания в другие системы.
- Заказывать исходящие/групповые звонки и отправлять SMS — не нужно для управленческой задачи, но возможность есть.
- Подписаться на события звонков через webhook.

### Что НЕЛЬЗЯ сделать через VPBX API

- **Удалять записи разговоров.** В ЛК это работает (batch select + кнопка «Удалить»), но соответствующий endpoint в публичной документации не выставлен. Управлять размером хранилища можно только так:
  - **Автоудаление по сроку** в настройках ЛК — максимум 365 дней.
  - **Перезапись поверх старых** при заполнении хранилища (настройка ЛК).
  - **Удаление руками** в ЛК или через browser automation.
- **Изменять настройки тарифа, услуг, договоров.** Это сознательно вынесено за пределы API.

### SDK-обёртки

- [Bobrovskih/mango-vpbx](https://github.com/Bobrovskih/mango-vpbx) — NodeJS SDK.
- [Sharoff45/mango-office-api](https://github.com/Sharoff45/mango-office-api) — PHP.

Для проекта «Тепло» SDK не обязателен — REST-вызовы простые, обёртку можно написать в одном файле `research/scripts/mango/vpbx_client.py` после получения ключей.

## 3. Speech Analytics: транскрипты разговоров

### Что это

Отдельный продукт Mango Office (платный, в составе тарифа или докупается).

- Распознавание речи: 3iTech или Yandex SpeechKit на выбор.
- Демо-режим: 7 дней, 100 минут разговоров.
- 32 бесплатных словаря для анализа тематики.
- Возможности: тематика разговора, ключевые слова, оценка эмоций, доли молчания/одновременной речи.

### Авторизация

- Отдельный токен в ЛК Mango → «Коллтрекинг → Настройки → API → Токен».
- НЕ путать с `api_key`+`api_salt` VPBX API.

### Что можно автоматизировать

- Получать готовые транскрипты разговоров по `call_id`.
- Подписаться на webhook `Конец звонка` для пуша готовых транскриптов в нашу систему.
- Прогонять транскрипты через LLM для своих метрик: жалобы, возражения, качество обслуживания, частые вопросы.

### Открытый вопрос

Подключён ли вообще Speech Analytics в текущем тарифе Mango у проекта «Тепло» — пока неизвестно. Уточнить у владельца перед использованием.

## 4. Управление хранилищем записей

Mango хранит записи разговоров в облачном хранилище. Срок хранения по умолчанию неограничен.

| Параметр | Значение |
| --- | --- |
| Срок хранения по умолчанию | неограничен |
| Автоудаление по сроку (настройка ЛК) | максимум 365 дней |
| Перезапись при заполнении | настройка ЛК, опционально |
| Удаление через API | **не поддерживается** в публичном API |
| Удаление через UI | поддерживается, в т.ч. batch |
| Задержка фактической очистки места | до 24 часов после удаления |

Документация: [Запись разговоров — настройка услуг](https://www.mango-office.ru/support/virtualnaya_ats/nastroyka_uslug/zapis_razgovorov_tb/), [Облачное хранилище](https://www.mango-office.ru/support/virtualnaya_ats/video/oblachnoe_khranilishche/).

**Практическое правило для проекта:** если нужно регулярно освобождать место — настроить автоудаление в ЛК на разумный срок (например, 90-180 дней) и параллельно архивировать важные записи локально через VPBX API до того, как они удалятся в облаке.

## 5. Связь с управленческими метриками

Из [02-metrics-tree.md](/business-docs/portrait/metrics-tree.md), блок «Операции», есть метрика **«потерянные звонки» / конверсия телефонии в заказ**. Сейчас она не считается, потому что нет источника. После подключения VPBX API она становится доступной:

| Метрика дерева | Как считать из VPBX API | Частота |
| --- | --- | --- |
| Входящие звонки | `stats/result` за период, фильтр `incoming` | Ежедневно |
| Пропущенные звонки | `stats/result`, фильтр по статусу «не отвечен» | Ежедневно |
| Конверсия в заказ | сверка времени звонка с временем заказа iiko по номеру клиента | Еженедельно |
| Среднее время ответа на звонок | агрегат `stats/result` | Еженедельно |
| Длительные разговоры (>5 мин) | агрегат + анализ через Speech Analytics | Еженедельно |

Эта связка перестаёт быть гипотетической после получения `api_key`+`api_salt` от владельца.

## 6. Текущий статус и что нужно от владельца

| Контур | Статус | Что нужно от владельца |
| --- | --- | --- |
| LK Финансы (строка `Телекоммуникации`) | Заблокирован | Выбрать путь A/B/C/D/E (см. выше) |
| VPBX API | Не подключен | Выпустить `api_key`+`api_salt` в ЛК → «Интеграции», положить в `.env` как `MANGO_VPBX_API_KEY` и `MANGO_VPBX_API_SALT` |
| Speech Analytics API | Не подключен | (а) Подтвердить, что сервис подключён в тарифе. (б) Если да — выпустить токен в ЛК → «Коллтрекинг → Настройки → API», положить в `.env` как `MANGO_SPEECH_ANALYTICS_TOKEN` |
| Webhook «Конец звонка» | Не настроен | Решить, нужен ли push в режиме реального времени или хватает batch-выгрузки через `stats/*` |
| Хранилище записей | Не настроено правило очистки | Решить срок автоудаления (предложение по умолчанию: 180 дней с локальным архивом важных записей) |

## 7. Следующие шаги по приоритету

1. **Выбрать путь для строки `Телекоммуникации`** (A–E). Это закрывает 1 строку P&L, ~14k ₽/мес.
2. **Выпустить `api_key`+`api_salt` VPBX API.** Это разовая 5-минутная операция в браузере. Даёт доступ к истории звонков и записям, открывает метрики «потерянные звонки / конверсия / время ответа».
3. **Уточнить подключение Speech Analytics.** Если есть в тарифе — выпустить токен; если нет — отложить, это не критично для управленческой панели первого приоритета.
4. **Настроить автоудаление записей** (после п.2), чтобы не упереться в лимит хранилища.
