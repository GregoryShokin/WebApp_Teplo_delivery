# Карта каналов маркетинговых данных

*Собрано: 2026-06-17. Цель — единый справочник: откуда брать маркетинговую информацию, какой endpoint, что он даёт, как подключаться. Для каждого канала — таблица endpoint'ов.*

**Статусы:** ✅ рабочий (есть доступ/скрипт) · 🖐 ручной (кабинет, не API) · ⛔ дыра (доступ не открыт) · ☠️ мёртвый (не использовать)

**Доступ (сокращения):** `.env` — ключ в переменных окружения · `сессия` — cookie владельца в браузере (Claude in Chrome) · `коннектор` — MCP-интеграция · `кабинет` — ручной вход.

## 1. iiko Cloud — `https://api-ru.iiko.services`
*Доступ: `IIKO_CLOUD_API_LOGIN` / `IIKO_CLOUD_API_KEY` (.env). Скрипт: `integrations/iiko/scripts/iiko_cloud.py`. Кэш: `research/raw/iiko/cloud_deliveries/`.*

| Endpoint | Метод | Что даёт | Доступ | Статус |
|---|---|---|---|---|
| `/api/1/access_token` | POST | Токен сессии | .env | ✅ |
| `/api/1/organizations` | POST | ID организации | .env | ✅ |
| `/api/1/deliveries/by_delivery_date_and_status` | POST | Заказы доставки: оплата баллами (списание), `customer`, статусы, таймстемпы скорости, гео-зоны, payment mix, `marketingSource` | .env | ✅ |

*Ограничение: текущие балансы баллов на картах НЕ отдаёт — только история списания.*
*Даёт для маркетинга: бонусная программа (списание), клиенты, скорость/опыт доставки, гео.*

## 2. iiko Server (OLAP) — iikoServer Resto, `/reports/olap`
*Доступ: `IIKO_SERVER_BASE_URL` + `IIKO_SERVER_TOKEN` (или `LOGIN`+`PASSWORD_SHA1`) (.env). Скрипты: `integrations/iiko/scripts/export_orders_delivery.py`, `analyze_*.py`. Артефакты: `research/processed/iiko/`.*

| Endpoint / источник | Метод | Что даёт | Доступ | Статус |
|---|---|---|---|---|
| `/reports/olap` (reportType SALES) | POST | Продажи по блюдам, ABC-анализ, чеки, выручка по направлениям; поля `Bonus.Sum`, `PayTypes`, `DishDiscountSumInt`, `Delivery.CustomerPhone` | .env | ✅ |
| OLAP по `Delivery.CustomerPhone` | POST | **RFM / retention** (повторные, межзаказный интервал, LTV-окно) | .env | ✅ |
| OLAP по типам скидок | POST | **Скидочная нагрузка / самые активные акции по деньгам** (шкала подарков, «скидка для доставки», iikoCard) | .env | ✅ |
| `assemblyCharts` (техкарты/BOM) | GET | Состав сетов/блюд до ингредиентов; защита компонентов при чистке меню | .env | ✅ `research/raw/iiko/promo_sets/assemblyCharts_getAll_iso.json` |
| `/v2/entities/products/list` | GET | Номенклатура: тип (DISH/GOODS/MODIFIER), `defaultIncludedInMenu` (активные позиции), `placeType` (станция/цех) | .env | ✅ `research/raw/iiko/products_list.json` |

*Даёт для маркетинга: меню-экономика, ABC, retention/RFM, скидки/акции, состав сетов.*

## Сводка дыр (что недостижимо сейчас)
- **Атрибуция app-заказов по источнику** — AppMetrica не отдаёт прямой группировкой; нужны трекеры на каналах (план: трекеры приложения).
- **Директ API** — доступ припаркован (заявка).
- **Балансы баллов на картах** — iiko Cloud отдаёт только историю списания.
- **Сквозной путь «посетитель→1-й заказ»** по всем каналам — нет дедупа сайт↔приложение↔телефон.
