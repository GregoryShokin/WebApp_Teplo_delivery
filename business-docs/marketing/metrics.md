# Маркетинговые показатели для стратегии

Дата фиксации: 2026-05-22.

## Цель

Этот документ определяет, какие маркетинговые показатели нужны бизнесу "Тепло" для выбора стратегии роста: какие каналы масштабировать, сколько можно платить за заказ и клиента, где теряются клиенты, какие акции действительно дают прибыль, а какие только покупают выручку скидкой.

Главная мысль: маркетинг нельзя оценивать только по заказам и выручке. Для стратегии нужны три слоя одновременно:

1. Спрос: сколько заказов и денег приходит.
2. Клиентская база: кто новый, кто возвращается, кто ушел.
3. Экономика: сколько маржи остается после скидок, себестоимости, доставки, комиссий и маркетинговых затрат.

## Главная маркетинговая цель

```text
Прибыльный рост = больше заказов от нужных клиентов x положительная маржа x контролируемая стоимость привлечения
```

Для доставки пиццы и роллов маркетинг должен отвечать не на вопрос "сколько потратили на рекламу", а на вопрос:

```text
Какие каналы и клиентские сегменты можно масштабировать без ухудшения прибыли и операционного качества?
```

## Уровни показателей

| Уровень | Главный вопрос | Пример решения |
| --- | --- | --- |
| Ежедневный контроль | Выполняем ли план спроса сегодня? | Усилить смену, запустить быструю акцию, проверить просадку канала |
| Еженедельный контроль | Какие каналы, продукты и сегменты растут или проседают? | Перераспределить бюджет, изменить оффер, проверить звонки/сайт/приложение |
| Ежемесячная экономика | Окупается ли маркетинг с учетом маржи? | Увеличить/срезать бюджет, сменить подрядчика, пересобрать акции |
| Стратегия | Где устойчивый источник роста? | Выбрать фокус: новые клиенты, удержание, реактивация, приложение, район, продукт |

## 1. Спрос и выручка

Эти метрики показывают, есть ли рост верхней воронки и где именно появляется спрос.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Заказы | `COUNT(orders)` или iiko `OrderNum` | iiko OLAP `/reports/olap` | Видеть спрос и нагрузку на кухню/курьеров |
| Выручка со скидкой | `SUM(DishDiscountSumInt)` | iiko OLAP | Сравнивать каналы и дни по фактической выручке |
| Выручка до скидки | `SUM(DishSumInt)` | iiko OLAP | Видеть, сколько выручки куплено скидкой |
| Средний чек | `Выручка со скидкой / Заказы` | iiko OLAP | Управлять сетами, допродажами, минимальной суммой заказа |
| Заказы по каналу | `Заказы` в разрезе `OriginName`, `OrderType`, `Delivery.ServiceType`, `PayTypes` | iiko OLAP | Понимать, откуда приходит оборот |
| Доля канала | `Заказы канала / Все заказы` или `Выручка канала / Вся выручка` | iiko OLAP | Не зависеть от одного источника |
| Выручка по дням недели | `AVG(дневная выручка)` по weekday | iiko OLAP | Планировать смены, закупки и акции |
| Выручка по часам | `SUM(выручка)` по часу открытия заказа | iiko OLAP `HourOpen` | Планировать кухню, рекламу и курьеров по пикам |

Качество данных: `OriginName` сейчас нельзя считать чистым каналом без проверки, потому что в текущем срезе есть большая доля пустых значений. Для стратегии нужен отдельный контроль `Доля заказов без источника`.

## 2. Привлечение и рекламные каналы

Эти метрики показывают, сколько стоит получить заказ и нового клиента.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Расход канала | `SUM(ad_spend)` | рекламные кабинеты, Biz Panel, ЭДО, банк | Контроль бюджета |
| Показы | `impressions` | рекламные кабинеты | Оценка охвата |
| Клики | `clicks` | рекламные кабинеты | Оценка трафика |
| CTR | `Клики / Показы` | рекламные кабинеты | Проверка креативов и оффера |
| CPC | `Расход / Клики` | рекламные кабинеты | Контроль цены трафика |
| Визиты/сессии | `sessions` | сайт/приложение, аналитика | Видеть переход от рекламы к заказу |
| Конверсия в заказ | `Заказы / Визиты` | сайт/приложение + iiko | Проверять сайт, приложение, меню, оплату |
| CPA заказа | `Расход канала / Заказы канала` | реклама + iiko | Понимать цену заказа |
| Новые клиенты | `COUNT(customer_hash)` с первым заказом в периоде | iiko private customer mart | Понимать рост базы |
| CAC | `Расход на привлечение / Новые клиенты` | реклама + iiko customer mart | Решать, можно ли масштабировать канал |
| Первый заказ: выручка | `SUM(first_order_revenue)` | iiko customer mart | Понимать качество привлечения |
| Первый заказ: маржа | `first_order_revenue - variable_costs - discount - commission` | iiko + P&L rules | Не покупать новых клиентов в убыток без осознанной окупаемости |

Важно разделять:

| Показатель | Что означает |
| --- | --- |
| `CPA заказа` | сколько стоит любой заказ из канала |
| `CAC` | сколько стоит именно новый клиент |
| `Цена повторного заказа` | сколько стоит вернуть уже известного клиента |

Для стратегии CAC важнее CPA, потому что один новый клиент может сделать несколько заказов.

## 3. Клиентская база и удержание

Эти показатели отвечают на главный вопрос: растет ли активная база или бизнес каждый месяц заново покупает один и тот же спрос.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Уникальные клиенты | `COUNT(DISTINCT customer_hash)` | iiko private customer mart | Размер клиентской базы |
| Активные клиенты 30/60/90 | клиенты с заказом за последние `N` дней | iiko customer mart | Видеть живую базу |
| Новые клиенты | первый заказ клиента внутри периода | iiko customer mart + `Delivery.CustomerCreatedDateTyped` | Оценка привлечения |
| Повторные клиенты | клиенты, у которых был заказ до периода | iiko customer mart | Оценка удержания |
| Доля повторных заказов | `Заказы повторных клиентов / Все заказы` | iiko customer mart | Понимать зависимость от базы |
| Repeat purchase rate | `Клиенты с 2+ заказами / Новые клиенты когорты` | iiko customer mart | Оценка качества первого опыта |
| Retention D30 | клиенты когорты, сделавшие повторный заказ в 30 дней | iiko customer mart | Сравнение каналов и акций по удержанию |
| Retention D60/D90 | аналогично за 60/90 дней | iiko customer mart | Понимание средней возвращаемости |
| Частота заказов | `Заказы / Активные клиенты` за период | iiko customer mart | Управление CRM, акциями, подписками |
| Средний интервал между заказами | среднее/медиана дней между заказами клиента | iiko customer mart | Настройка коммуникаций и реактивации |
| Спящие клиенты | нет заказа `N` дней | iiko customer mart | Сегменты для возврата |
| Реактивированные клиенты | был спящим, затем сделал заказ | iiko customer mart | Оценка реактивационных кампаний |

Для "средней жизни клиента" использовать две метрики:

| Метрика | Формула | Комментарий |
| --- | --- | --- |
| Наблюдаемая жизнь клиента | `last_order_date - first_order_date` | Считать медиану, среднее и перцентили; новые клиенты еще не успели проявить полную жизнь |
| Активная жизнь клиента | период от первого заказа до момента, когда клиент считается ушедшим | Например, клиент ушел, если нет заказа 90 или 120 дней |

Не смешивать "среднюю жизнь" с retention. Retention говорит, сколько клиентов вернулось к конкретному сроку. Средняя жизнь говорит, как долго клиент остается экономически активным.

## 4. LTV и окупаемость клиента

LTV нужен, чтобы понять, сколько можно платить за привлечение.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Revenue LTV | `SUM(выручка клиента)` | iiko customer mart | Грубая ценность клиента |
| Gross Margin LTV | `SUM(выручка - food cost - скидки - комиссии - доставка)` | iiko + P&L allocation | Реальная ценность клиента |
| Cohort LTV | `SUM(маржа когорты) / Клиенты когорты` | iiko customer mart | Сравнение каналов привлечения |
| LTV 30/60/90 | накопленная выручка/маржа за 30/60/90 дней после первого заказа | iiko customer mart | Быстрая оценка окупаемости |
| LTV/CAC | `Gross Margin LTV / CAC` | iiko + реклама | Решение о масштабе канала |
| Payback period | первый день/месяц, когда накопленная маржа покрыла CAC | iiko + реклама | Понимать срок возврата рекламных денег |
| Допустимый CAC | `ожидаемый Gross Margin LTV x целевая доля на привлечение` | управленческая модель | Устанавливать лимиты ставок и бюджетов |

Рабочее правило: для управленческих решений по росту использовать не `Revenue LTV`, а `Gross Margin LTV`. Выручка без маржи может обмануть.

## 5. ROMI и прибыльность маркетинга

ROMI должен считаться после маржи, иначе скидки и дорогая доставка могут создать иллюзию эффективности.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Revenue ROMI | `(Выручка канала - Расход) / Расход` | iiko + рекламные расходы | Быстрый, но грубый показатель |
| Gross ROMI | `(Валовая маржа канала - Расход) / Расход` | iiko + food cost + реклама | Базовый показатель для решений |
| Contribution ROMI | `(Маржа после переменных расходов - Расход) / Расход` | iiko + P&L rules | Лучший показатель для стратегии |
| Marketing cost share | `Расход маркетинга / Выручка` | P&L + реклама | Контроль бюджета |
| Profit by channel | `Выручка - food cost - скидки - доставка - комиссия - маркетинг` | iiko + P&L allocation | Выбор каналов для масштабирования |

Если канал дает много заказов, но низкий Contribution ROMI, его нельзя масштабировать без изменения оффера, скидок, логистики или среднего чека.

## 6. Акции, скидки и промо

Акции нужно оценивать не по приросту заказов, а по марже и повторным заказам после акции.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Сумма скидок | `SUM(DiscountSum)` | iiko OLAP | Контроль цены акции |
| Доля скидки | `Скидки / Выручка до скидки` | iiko OLAP | Понять, не покупаем ли оборот слишком дорого |
| Заказы с промо | заказы с купоном/акцией/типом скидки | iiko OLAP + loyalty fields | Оценка масштаба акции |
| Средний чек промо | `Выручка промо / Заказы промо` | iiko OLAP | Проверка роста корзины |
| Маржа промо | `Выручка промо - food cost - скидки` | iiko OLAP | Оценка прибыльности акции |
| Incremental orders | заказы сверх базового прогноза | iiko + план/факт | Отличить реальный прирост от скидки постоянным клиентам |
| Repeat after promo | повторный заказ после участия в акции | iiko customer mart | Понять, приводит ли акция качественных клиентов |

Для сетов и акционных наборов важно использовать восстановленную себестоимость по компонентам, а не нулевую себестоимость родительской строки.

## 7. Каналы, источники и атрибуция

Это не столько метрики роста, сколько контроль качества данных. Без них стратегия будет строиться на мутной воде.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Доля заказов без источника | `Заказы с пустым OriginName / Все заказы` | iiko OLAP | Контроль атрибуции |
| Доля заказов с marketing source | `Заказы с Delivery.MarketingSource / Все заказы` | iiko OLAP | Проверить настройки сайта/приложения/агрегаторов |
| Несоответствие sourceKey vs marketingSource | заказы, где источник заказа и маркетинговый источник конфликтуют | iikoTransport + iikoServer | Чистка справочника |
| Unknown revenue | выручка заказов без источника | iiko OLAP | Размер слепой зоны |
| Source coverage by channel | доля заполненности источника по сайту, приложению, телефону, агрегаторам | iiko + сайт/телефония | Где ломается разметка |
| Дубликаты клиентов | несколько телефонов/карт/имен для одного клиента или наоборот | private customer mart | Чистка базы и точность LTV |

Минимальное правило: пока доля неизвестного источника высока, нельзя делать жесткие выводы о ROMI по каналам.

## 8. Сервисные метрики, влияющие на маркетинг

Маркетинг не живет отдельно от качества. Плохая доставка или отмены съедают retention и LTV.

| Метрика | Формула | Основной источник | Решение |
| --- | --- | --- | --- |
| Отмены | количество и сумма отмен | iiko OLAP `OrderDeleted`, `Delivery.CancelCause` | Понять потерянный спрос |
| Возвраты | `DishReturnSum.withoutVAT` | iiko OLAP | Контроль ошибок и качества |
| Опоздания | `Delivery.DelayAvg`, доля заказов с задержкой | iiko OLAP/delivery reports | Связь SLA с повторными заказами |
| Время в пути | `Delivery.WayDurationAvg` | iiko OLAP | Логистика и районы |
| Оценка доставки/кухни | средняя оценка и количество оценок | Greevy/iiko delivery marks | Качество продукта и сервиса |
| Жалобы | количество, тип, сумма компенсаций | Greevy/мессенджеры/iiko | Приоритеты исправлений |
| Пропущенные звонки | пропущенные / входящие | Mango Office | Потерянные заказы |
| Конверсия звонка в заказ | заказы после звонка / принятые звонки | Mango + iiko по телефону/времени | Эффективность администраторов и телефонии |

Для стратегии эти показатели нужны, чтобы отличить маркетинговую проблему от операционной. Если реклама привела спрос, но доставка опаздывает, падение повторов нельзя лечить только новым бюджетом.

## 9. Сегментация клиентов

Сегменты нужны для разных стратегий роста.

| Сегмент | Как определить | Что делать |
| --- | --- | --- |
| Новые | первый заказ в периоде | Проверять CAC, первый опыт, повтор D30 |
| Повторные активные | 2+ заказа и последний заказ недавно | Удерживать, повышать частоту, допродавать |
| VIP / top RFM | высокая частота и сумма | Персональные офферы, ранний доступ к новинкам |
| Спящие 30/60/90 | нет заказа N дней | Реактивация разными офферами |
| Реактивированные | вернулись после периода сна | Оценить эффективность возвратных кампаний |
| Скидочные | большая доля заказов с промо | Проверить маржу и зависимость от скидок |
| Самовывоз | `Delivery.ServiceType=PICKUP` | Отдельный оффер и средний чек |
| Доставка | `Delivery.ServiceType=COURIER` | Контроль SLA, районов, минимальной суммы |
| Канальные когорты | первый источник клиента | Сравнивать LTV/CAC по источникам |

RFM-основа:

```text
R = recency: сколько дней с последнего заказа
F = frequency: сколько заказов за период
M = monetary: сколько выручки или маржи принес клиент
```

## 10. Минимальный набор для стратегии

Если выбирать только показатели, без которых нельзя принимать стратегические решения, то первый набор такой:

| Приоритет | Показатель | Почему важен |
| --- | --- | --- |
| 1 | Заказы, выручка, средний чек по дням и каналам | Базовый спрос |
| 2 | Доля неизвестного источника | Понимание качества атрибуции |
| 3 | Расход, CPA заказа, CAC по каналам | Цена роста |
| 4 | Новые и повторные клиенты | Рост базы против "покупки текущего оборота" |
| 5 | Retention D30/D60/D90 по когортам | Качество привлечения и продукта |
| 6 | Gross Margin LTV и LTV/CAC | Можно ли масштабировать канал |
| 7 | ROMI по марже | Окупается ли маркетинг |
| 8 | Скидки и промо-маржа | Не съедаем ли прибыль акциями |
| 9 | Отмены, возвраты, опоздания, оценки | Операционные причины падения повторов |
| 10 | RFM и спящие клиенты | Потенциал CRM и реактивации |

## 11. Источники данных для метрик

| Источник | Что дает | Статус |
| --- | --- | --- |
| iikoServer OLAP `/reports/olap` | заказы, выручка, скидки, себестоимость, каналы, доставка, отмены, возвраты | подключен |
| iikoServer OLAP DELIVERIES columns | клиентские поля доставки: дата создания клиента, телефон, карта, реклама клиента | найдено, требует private-обработки |
| iikoTransport/iikoCloud | создание/статусы заказов, marketingSourceId/sourceKey, справочники маркетинговых источников, loyalty customer info | использовать как операционный слой |
| Biz Panel / Яндекс Директ | бюджет, показы, клики, CPC | найден частично |
| VK/таргет | расходы, показы, клики, аудитории | требует подключения/выгрузки |
| Sber/T-Bank | факт оплат подрядчикам и рекламным кабинетам, сверка расходов | подключено частично |
| ЭДО/почта | счета, акты, УПД по маркетингу и сервисам | частично найдено |
| Mango Office | звонки, пропущенные, конверсия звонок -> заказ | источник описан, требует выгрузки |
| Greevy/отзывы | оценки, жалобы, NPS-like показатели | требует отдельного разбора |
| Сайт/приложение | визиты, события, воронка, источник установки/заказа | требует подключения/выгрузки |

## 12. Правила безопасности данных

Клиентская аналитика требует персональных полей: телефон, имя, карта, адрес. Поэтому:

1. Raw с PII хранить только в private/raw.
2. В processed выводить `customer_hash`, агрегаты и сегменты без телефона/ФИО.
3. Хеш считать стабильно с солью из `.env`, не писать соль в документы.
4. В публичные Markdown-отчеты не выводить телефоны, имена, адреса, номера карт.
5. Любой отчет до уровня клиента должен иметь отдельный статус доступа.
