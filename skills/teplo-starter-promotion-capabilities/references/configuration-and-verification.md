# Настройка и проверка Starter

Контракт прочитан 07.10.2026: [OpenAPI Тепла](https://crm.starterapp.ru/fmteplo/api/v1/openapi.json),
`info.version=0.1.0`, base `/fmteplo`. UI текущего реестра — CRM v2.22.0. Все пути ниже
добавляются к `https://crm.starterapp.ru/fmteplo`; актуальность контрактов/прав проверять
перед применением. Схема описывает поля, а не гарантирует доступность тарифа или UI.

## Рабочий путь новой акции

1. В рамках оценки составь проект конфигурации: тип награды, SKU/размер, аудитория,
   канал/способ получения, порог/его база, срок, лимиты, приоритет и совместимость.
2. Сверь реальные товары и техкарты, текущие акции, iiko provider и POS-связи.
   Рассчитай худшую допустимую корзину, включая все копии/модификаторы.
3. При отдельной авторизации настройки открой CRM → Маркетинг → Акции, выбери
   скидку, промокод или надбавку. Сверь поля с этим проектом. Для рефералов нужны
   отдельная скидка с признаком referral и программа; для надбавки сначала связь iiko.
4. До публикации согласованного предложения установи, как проверять: подходящая
   корзина, неподходящая, границы суммы/даты/лимита, конкурирующая скидка/баллы,
   недоступный подарок, отмена. Используй доступную изолированную среду либо уже
   существующий обезличенный факт; реальный заказ/начисление/отправка требует своей
   авторизации. Не создавать «тест» с производственным эффектом без неё.
5. После разрешённого изменения сохранить ID/изменённые поля/дату и фактический
   результат. Конфигурация, применение, платёж, баллы и сообщение — разные проверки.

Оценка идеи или создание скилла разрешает сбор сведений и проекта, а не шаг публикации.

## Скидки, подарки, коды: поля

`GET /api/v1/frontend/promotions/{discounts|promocodes|increases}` и `/{starter_id}` —
список/деталь; создание `POST` коллекции, изменение `PUT` детали, статус `PATCH .../status`.
Для точного тела изменения читать свежую схему; не превращать GET-ответ в PUT вслепую.
Пагинация/источники подробно в [методе обновления реестра](../../teplo-promotions/references/sources-and-refresh.md).

| Настройка | Контракт | Проверка/ограничение |
|---|---|---|
| Награда | `type=percent/absolute/meal/doubleMeal`; `value.size` или `value.mealId` | `stampCard` в общем enum не доказывает любую комбинацию типа с каждым endpoint |
| Канал | `placeActivation=all/app/web` | Отдельно проверить приложение/сайт и версию |
| База скидки | `fieldToApply=price/totalPrice/deliveryPrice` | База скидки не равна базе минимального порога |
| Минимум | `minOrderPriceCommon`, `minOrderPriceSettings.type=common/deliveryType`, delivery/pickup/indoor | Учитывается до или после выгоды — подтверждать, не угадывать |
| Меню для порога | `minOrderPriceSettings.dependOnMeals=all/chosen` | Условия выбранного меню и наградного блюда не смешивать |
| Меню / магазины | `menuRestrictions.meals/categories/shops`: `choice`, `entityIds` | `toChosen` включает, `exceptChosen` исключает; пустое и null не тождественны |
| Способ получения | `deliveryType.choice/entityIds` | Не подменять каналом app/web |
| Время | `dateTimeRestriction.date[]/time[]/daysOfWeek/choice` | Часовой пояс, границы и время предзаказа уточнять |
| Первый заказ | `firstOrderOnly` | Мануал учитывает сайт и приложение; учёт старых офлайн-заказов не подтверждён |
| День рождения | `birthdayOptions.daysBefore/daysAfter/usageCount` | Достоверность/повторное изменение даты — отдельный вопрос |
| Лимиты | `usagesCap`, `availableCountForUser`, `repeatable` | Не сводить три поля к одному; неизвестный смысл хранить явно |
| Порядок | `sortIndex`, `lastApplicable` | Больше sortIndex — позже; остановка касается последующих скидок, равный индекс не разрешён автоматически |
| Цель / referral | У скидки: `goal`, тексты цели, `linkedDiscountId`, `isReferral` | Виджет сам не исполняет выгоду |
| Массовые коды | У промокода: `isBulk`, `bulkDiscountMaxUsages`, `onlyOnePromocodePerDiscount` | Возможности лимитов подтверждены UI 08.10 ниже; соответствие этим полям не доказано |
| Надбавка | percent/absolute, `separateInReceipt` | По мануалу процент округляется вверх; нужна POS-связь |

[Официальная скидка](https://wiki.starterapp.ru/1b98155b77798087bb5dc47e61f358bf?pvs=21)
подтверждает порядок и первый заказ.
[Удвоение](https://wiki.starterapp.ru/2a98155b77798082b4e8c27bd06bf9fc?pvs=21)
дублирует все подходящие блюда и топпинги. Для удвоения по промокоду инструкция не
допускает виджет цели и настройку реферальной акции, в отличие от обычной скидки.

## Массовые коды: настройка отдельных компонентов

| Операция | Путь `/api/v1/frontend/...` | Существенные параметры / предел |
|---|---|---|
| Правило кампании | `promotions/promocodes` POST | `isBulk=true`, награда и ограничения |
| Генерация | `promocodes/generate` POST | `discountId`, quantity 1–20000, length 4–8, prefix длиной 1–8 |
| Импорт | `promocodes/import` POST | `codes` 1–20000, nullable discountId, dryRun default false |
| Результат импорта | Ответ import | added; неверный формат; дубли внутри запроса; уже существующие коды |
| Список экземпляров | `promocodes` GET | id, code, status, usageLimitTotal, usageLimitPerGuest, usageCount, discount |
| Кампании | `promocodes/discounts/bulk` GET, `promotions/promocodes?is_massive=true` GET | Не смешивать кампанию и экземпляр |
| Счётчики / экспорт | `promocode/total`, `promocode/export` GET | all, active, used, disabled; счётчик не доказывает выдачу |
| Включение / отключение | `promocodes/activate`, `promocodes/deactivate` POST | Изменяющие операции; тело из свежей схемы |

Лимит 20000 — предел одного запроса по схеме, не месячная квота и не обещанная
скорость выдачи. UI 08.10 называет длину случайной части отдельным полем; соответствие
API-полю length проверять перед автоматизацией. Импорт с default
`dryRun=false` изменяет данные; его нельзя использовать как пробное чтение.
В `PromoCodeListItem` нет подтверждённой привязки победителя/владельца кода.
Дальнейшая персональная выдача описана в [ограничениях](current-constraints-2026-10-07.md).

[Одиночные/массовые коды](https://starter-app.notion.site/1b98155b777980388758f893ed565826)
и [релиз апреля 2026](https://starterapp.ru/updates) подтверждают продуктовую функцию,
но не готовность сквозного конкурса Тепла.

## Совместимость: проверить все применимые слои

| Слой | Поля / источник | Почему важен |
|---|---|---|
| Очередь акций | sortIndex, lastApplicable, текущие карточки | Остановка последующих скидок по UI 08.10 явно не включает бонусные баллы |
| Баллы + скидки/коды | `LoyaltyProgramData.canUseWithPromocode/canBeUsedWithDiscounts` | Независимые глобальные ограничения |
| Лимит/база баллов | withdrawPercent, refillFromClean, calculateWithoutDelivery, allowUseBonusesOnWeb | Меняет реальную выгоду и денежную часть |
| Меню для баллов | `/loyalty_program/bonus-restriction`, restrictAward/restrictRedeem | Тип запрета общий для проекта; модификаторы наследуют блюдо |
| Комбо | `/catalog/combo/settings`: discountsIncludeCombos, promocodesIncludeCombos, bonusesSpendingIncludesCombos | Defaults false не являются прочитанной конфигурацией |
| Внешний движок | iikoCloud программа/категория/PaymentAction | Лимит или порядок движка может отличаться от UI Starter |
| POS-заказ | Типы оплат/скидок/надбавок, доступные блюда | Корзина может рассчитать, а iiko не принять |

[Ограничения баллов](https://wiki.starterapp.ru/3ef8155b7779806c9fcbe74f1297f57e?pvs=21):
категория распространяет запрет на будущие блюда; индивидуальное ограничение
сохраняется после переноса блюда. Платные топпинги входят в ограничение блюда.

### Составная акция: подарок + удвоение + баллы

Для такой корзины дополнительно проверить:

- Сколько кодов принимает Starter одновременно и можно ли связать несколько выгод
  с одним кодом. `meal` и `doubleMeal` — разные типы награды; это не доказательство
  двух действий одной кампании. Правило «один купон» iiko не переносить на Starter.
- Если использовать код + автоматическое удвоение, проверить их порядок и аудиторию:
  автоскидка не становится доступной только участникам по факту рассылки кода.
- Несколько порций одного SKU, платные топпинги и подарок, который сам входит
  в ассортимент удвоения. Исключение бесплатного подарка из повторного удвоения
  и предел копий не установлены. Лимит кодов не ограничивает стоимость любой корзины.
- `canUseWithPromocode` / `canBeUsedWithDiscounts` относятся к общей программе.
  Возможность разрешить баллы только новой кампании не подтверждена. Оцени влияние
  глобального изменения на остальные предложения, не обещай отдельное исключение.

## Лояльность, триггеры и сообщения: маршруты

- `GET /api/v1/frontend/loyalty_program`: provider, selfRefill/selfWithdraw, уровни,
  лимиты и совместимость. **Ответ может содержать секреты подключения**: не сохранять
  целиком; читать безопасный экран или whitelist нужных бизнес-полей.
- `GET /api/v1/frontend/referral/program`, `/referral/settings`: награды сторон,
  minimum, связь со скидкой; личные реферальные коды в skill не переносить.
- `GET /api/v1/frontend/welcome_bonuses`, `/bonus_burning`: отдельные флаги/суммы/сроки.
  Starter-срок не переносить на внешнюю ПЛ.
- `GET /api/v1/frontend/server-settings/push`: общая/посценарная активация, retention,
  birthday, feedback, balance. Единицы времени брать из UI, не из целого числа.
- Рассылки: `POST /api/v1/frontend/distribution`, `/distribution/cluster`,
  `/distribution/customers`, `/distribution/customer` — изменяющие действия.
  `PushData` задаёт переводы title/body, template_id, link, image, subject, datetime.
- Получатели: `CustomerBodyFilters` — RFM, частота/давность/сумма/средний чек,
  баланс, дата рождения/регистрации, магазины/города, использованные акции/коды,
  customSegmentId, marketing_consent. Это отбор адресатов, не право применения кода.

По [инструкции рассылок](https://wiki.starterapp.ru/CRM-1b98155b77798092870ae7e1043e7fb4?pvs=21)
push сопровождается записью в центре уведомлений даже при недоставленном push.
Есть расписание, язык, ссылка, переменные имени/баланса/любимого блюда/welcome;
заголовок до 30, текст до 140 символов — текущий UI/длину подстановки проверять.
Не считать найденной переменную уникального призового кода.

[Автоприменение кода](https://wiki.starterapp.ru/1d58155b777980318eece344986c4c0d?pvs=21):
`https://<сайт>/?promocode=<код>`, в том числе ссылка в push. Подстановка не отменяет
условия акции. Одна такая ссылка не распределяет автоматически разные коды гостям.

## Доказательство исполнения и результата

GET `/api/v1/frontend/distributions`, `/distribution/{distribution_id}`,
`/distribution/{distribution_id}/counts` дают состояние и агрегаты. В контракте
есть attributionWindowHours, visits, orders, ordersSum. Покрытие автоматических
trigger-push этими журналами надо подтвердить, не обещать по названию.

GET `/api/v1/frontend/customers/{customer_id}/main-bonus-program-transactions`
и `/bonus-program-transactions` — маршруты проверки начислений/списаний.
Совпадение суммы +100 не устанавливает происхождение операции без других признаков.
Клиентские контакты, ID и балансы не включать в переносимый skill.

Для эффекта акции сопоставляй расходы и прибыль с контрольной группой; техническая
атрибуция не определяет, сделал бы клиент заказ и без предложения. Методы чтения,
пагинации и сохранения доказательств — в
[источниках реестра](../../teplo-promotions/references/sources-and-refresh.md).

CRM v2.22.0. Редактор закрыт через «Выйти без сохранения»; генерация, импорт,

### Подтверждённые элементы формы

Массовый тип описан как набор уникальных кодов для гостей или каналов. До добавления
кодов в черновике показан неактивный статус. Есть переключение генерации/импорта,
количество кодов, обязательный префикс (A–Z, 0–9, дефис, подчёркивание; до 8 символов)
и длина случайной части. Статические примеры формата не являются кодами, которые
уже можно выдать клиентам. Текущая роль видит настройку; успешная запись не проверена.

Форма награды предлагает проценты, рубли, бесплатное блюдо, удвоение. Базы — цена
блюда, общая сумма заказа, стоимость доставки. Каналы — приложение, сайт, все.
Есть первый заказ, минимум без ограничения/общий/по способу получения. Ограничения
разделены на время, ассортимент, локации, способ получения.

### Четыре лимита массового промокода

| Элемент UI | Что ограничивает | Подтверждённый смысл примера |
|---|---|---|
| Один и тот же код одним гостем | Использования конкретного кода гостем | При лимите 1 и общем лимите кода 5 — пять гостей по одному разу |
| Один и тот же код всеми гостями | Использования конкретного кода суммарно | Если лимит гостя выключен, один гость может повторять до общего лимита 5 |
| Все коды акции в сумме | Использования всей кампании | Проверять отдельно от ограничения отдельного кода |
| Один код акции для гостя | Использование гостем разных кодов той же кампании | Не приравнивать к персональной привязке заранее выбранного кода |

Если первые два переключателя выключены, UI описывает отсутствие лимита использований
**этого кода**; ограничения кампании, времени и прочих условий сохраняются.
Эти смыслы установлены по тексту UI. Не назначать им поля `repeatable`,
`bulkDiscountMaxUsages`, `onlyOnePromocodePerDiscount` без доказанного соответствия
сохранённому запросу/ответу или документации контракта.

Текст остановки последующих скидок явно делает исключение для бонусных баллов.
Поэтому одновременно проверять слой совместимости баллов; `lastApplicable` не
заменяет `canUseWithPromocode`/`canBeUsedWithDiscounts`. Персональная привязка
получателя не наблюдалась в прочитанных вкладках; существование такой функции
в других контурах остаётся отдельным вопросом.
