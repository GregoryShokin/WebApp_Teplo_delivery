# Возможности акций iiko для «Тепла»

Определяй, из каких настроек можно собрать предложение, чего не хватает в текущем
контуре и как это влияет на полную прибыль. Возможность iikoCard не переносится
автоматически в Starter, iikoFront или любой другой канал оформления.

## Выбор справки

- Для выбора механики — [карта возможностей](references/capability-map.md).
- Для точных мест настройки, чтения и проверки —
  [настройка и проверка](references/configuration-and-verification.md).
- Для подтвержденного состояния Тепла и решений владельца —
  [ограничения на 07.10.2026](references/current-constraints-2026-10-07.md).
- Текущие предложения, суммы и условия бери из
  [реестра акций](../teplo-promotions/SKILL.md), не из примеров справки iiko.
- Витрину, персональную выдачу и передачу в iiko сверяй с
  [возможностями Starter](../teplo-starter-promotion-capabilities/SKILL.md).
- Полную экономику считай по [юнит-экономике](../teplo-unit-economics/SKILL.md),
  направление изменений — по [стратегии прибыли](../teplo-profit-strategy/SKILL.md).

## Две оценки вместо одного «можно»

Для каждой идеи укажи отдельно:

| Ось | Значения |
|---|---|
| Поддержка платформой | Подтверждена; с ограничениями; не установлена; не поддерживается в указанном модуле/версии |
| Готовность Тепла | Уже настроено; нужны штатные настройки; нужна связка/разработка; нужен ручной процесс; не установлена |

Для «уже настроено» добавляй доказательство: **настройка прочитана** либо
**исполнение наблюдалось**. Доступный контрол не доказывает работающую цепочку.
«Нужны только настройки» допустимо, когда проверены все требуемые этапы и каналы.
Ошибка API и пустой список не доказывают отсутствие возможности.

## Как оценивать предложение

1. Запиши аудиторию, выгоду, требуемое действие, период и канал получения/использования.
2. Разложи механизм: условие → действие → исполнитель → учет. Назови связанные
   iiko-программу, акцию, блоки, тип оплаты и зависимость от Starter, если они нужны.
3. Установи базу порога/скидки, SKU/размеры, идентификацию гостя, кратность,
   лимит гостя и общий лимит, время, приоритет и сочетания с текущими правилами.
4. Дай две оценки готовности с источником и датой; назови конкретный отсутствующий шаг.
5. Сравни базу и сценарий по полной экономике, включая дополнительные смены при росте.
6. Предложи одну следующую проверку главного пробела. При необходимости исполнения
   сначала ищи обезличенный факт либо подходящую изолированную среду.

## Неподменяемые различия

- Программа → акция → блок → условие/действие — разные уровни. Порядок блоков важен.
  Массив bindings Cloud не считать доказательством порядка исполнения: у Тепла
  зафиксировано расхождение с нумерованными блоками UI.
- Купонная серия, генерация уникального кода, его персональная привязка, отправка,
  погашение и получение приза — отдельные возможности.
- По прямому сообщению владельца массовый конкурс с персональной рассылкой призовых
  кодов сейчас **не готов**. Обнаруженная кнопка выпуска купонов этого не меняет.
- Документировано: один купон iiko на заказ; автосборка комбо не работает при
  формировании доставки. Не обещай эти сценарии иначе без нового доказательства.
- Сообщение, начисление баллов, их списание, скидка и подарок не являются одним событием.
  Не обещай сочетание механик по настройке лишь одной системы.
- Датированный снимок не становится текущим автоматически. Перед конкретным
  предложением проверь только относящиеся к нему изменяемые настройки.

## Экономика и результат

Основная величина — `ΔП = Псценарий − Пбаза` за одинаковый период. Считай net-выручку,
продукты, упаковку, переменный труд и ступени ФОТ, доставку, комиссии, налоги,
стоимость настройки/обслуживания механики и реальные изменения постоянных расходов.
Скидку не вычитай повторно из net; подарок оценивай по затратам, а не меню;
начисленные и потраченные бонусы не складывай. Бесплатному push не назначай цену.
Неизвестные расходы не равны нулю, погашенный код не равен дополнительному заказу.

Выдай карточку: предложение → техническая сборка → две оценки готовности →
ограничения/сочетания → диапазон Δ прибыли и условия окупаемости → следующая проверка.
Создание навыка и исследование не разрешают менять программы, выпускать/импортировать
купоны, начислять бонусы, оформлять реальные заказы или отправлять сообщения.

Если владелец уже поручил конкретную настройку или запуск, действуй в пределах этого
разрешения; не запрашивай его повторно только из-за формулировок навыка.

Если объём будущей работы ещё неизвестен, так и укажи: «нужен отдельный проект;
доля штатной настройки и разработки пока не установлена». Без обязательных данных
для экономики показывай формулу и недостающие входы; диапазон прибыли не выдумывай.
