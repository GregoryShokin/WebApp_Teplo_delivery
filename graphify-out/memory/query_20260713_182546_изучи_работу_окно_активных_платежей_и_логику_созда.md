# Q: Изучи работу окно активных платежей и логику создания новых платежей через это окно.

## Answer

Expanded from original query via graph vocabulary: active, payments, payment, create, new, dialog, modal, window, draft, активных, платежей, создание. Текущая реализация устроена как два связанных контура. ActivePaymentsModal читает нормализованный агрегатор активных счетов, банковских черновиков, резервов Сейфа и Кассы и зарплатных банковских черновиков, раскладывает их по пяти корзинам и делегирует мутации профильным endpoint. Кнопка Создать открывает NewPaymentDialog. Оно получает с сервера статьи, кошельки и сотрудников, уже отфильтрованные по правам, и маршрутизирует операцию по flow статьи: свободный расход, предоплата, наличное поступление, аванс или заем, долг по зарплате и внутренний перевод. Банковский свободный расход создает один CounterpartyPaymentDraft на сумму строк; только после банковского paid перехода создаются транзит банк в Сейф и отдельный SafeAllocation по каждой строке. Наличные маршруты либо создают резерв, либо сразу проводят расход, либо перемещают деньги с целевым резервом. Терминальные операции из активного окна исчезают и остаются в истории. Выявлены потенциальные несогласованности: фронтовое действие payments.create не включает finance.safe.confirm_paid хотя сервер допускает отдельный income flow; supplier_invoices возвращается сервером, но не имеет формы или ветки selectArticle; pending банковские авансы и разовые выплаты сотрудникам не являются прямыми источниками агрегатора и видны только после появления общего резерва; флаги can_edit и can_cancel агрегатора почти не используются активной модалкой.
