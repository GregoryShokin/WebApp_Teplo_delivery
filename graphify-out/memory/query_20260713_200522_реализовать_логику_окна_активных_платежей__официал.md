# Q: Реализовать логику окна активных платежей: официальный контрагент с реквизитами оплачивается по реквизитам; официальный без реквизитов получает предупреждение и явное предложение вывести на карту ИП; неофициальный или невыбранный контрагент по умолчанию оплачивается на карту ИП; статусы банковских черновиков обновляются полингом.

## Answer

В изолированной ветке codex/counterparty-requisites-draft-poll добавлен обязательный маршрут по подтверждённым реквизитам, отдельный признак наличия реквизитов и серверно проверяемое явное согласие allow_official_via_safe только для официального контрагента с пустыми реквизитами. Если реквизиты существуют, согласие не обходит проверку. Интерфейс сбрасывает согласие при смене получателя, блокирует наличный источник и показывает действие Вывести на карту ИП. Ранее добавленный провайдерный полинг обновляет удалённые черновики и окно активных платежей. Проверено 53 backend-тестами и production-сборкой frontend.
