# Q: Посмотри ветку main, найди окно Новый контрагент и проверь логику модуля контрагентов и связь с ДДС

## Answer

Expanded from original query via graph vocab: [counterparty, counterparties, dds, cashflow, payment, supplier, iiko, ledger, category, invoice, transaction, link, debt, balance]. The screenshot is CreateCounterpartyDialog on warehouse registry. The main supplier flow shares the counterparty master with DDS and correctly records counterparty_id on cashflow facts. Official, informal-via-safe, and barter flows are structurally separated. Findings: DDS has a second bare counterparty CRUD that does not create supplier role/profile and uses inactive versus archived; created-from-operation remember_as_rule stores payload counterparty_id instead of resolved ID; operation split does not enforce invoice counterparty equals cashflow counterparty; manual DDS aliases are not consumed by bank classification; the create dialog preserves stale fields while resetting only the iiko selector, which can create an unlinked supplier. Ledger category is a registry grouping, not a DDS article.
