# Экономический блок

Дата фиксации: 2026-05-18.

## Назначение

Собрать первый экономический слой портрета бизнеса: выручка, себестоимость, валовая маржа, ФОТ, курьеры, расходы и ограничения данных.

Контур:
активная точка Черникова. Гагарина после января 2024 считается исторической и не смешивается с текущей экономикой.

## Ключевой источник выручки, скидок и food cost

Для восстановления технологии P&L первичный источник по выручке, скидкам и себестоимости по направлениям - iiko OLAP `Отчет о выручке по направлениям`.

Именно в нем нужно искать:

- выручку без учета скидок;
- выручку с учетом скидок;
- сумму скидки;
- себестоимость / food cost;
- направления `Роллы`, `Пицца`, `Горячий цех`, `Бар`.

Google Sheets `ОПиУ` использует эти значения как ручной перенос/управленческую раскладку. Processed-файлы вроде `iiko_monthly_gross_margin.csv` являются удобными агрегированными снимками для экономического блока, но при разборе методологии строки P&L следующий агент должен идти в OLAP `Отчет о выручке по направлениям`.

Управленческий маппинг направлений: `Роллы` = `Суши` + `Специи, роллы Черникова`; `Горячий цех` = `Шаурма`.

## Курьеры

Факт:
в API есть доступ к сохраненному отчету `P&L по складам`: `GET /resto/api/v2/reports/olap/byPresetId/8c13763a-35bf-9f27-017f-5468b1e70021`.

Источник:
iiko `/v2/reports/olap/presets`, preset `P&L по складам`, `reportType=TRANSACTIONS`, поля `Account.Type`, `Account.Name`, `Store`, `Sum.ResignedSum`.

Вывод:
это API-доступ к разделу `Финансы / Отчет о прибылях и убытках`. Даты для `byPresetId` работают в формате `YYYY-MM-DD`.
Важная поправка: `dateTo` у `byPresetId` является исключающей верхней границей. Для полного апреля 2026 нужно запрашивать `dateFrom=2026-04-01`, `dateTo=2026-05-01`, а не `dateTo=2026-04-30`.

Действие:
использовать строку `Зарплата курьеров` как основной источник курьерских расходов для P&L. Источник и сумма полного апреля 2026 подтверждены владельцем после сверки.

Вывод:

Действие:

## ОПиУ И ДДС

Факт:
найденный ОПиУ заполнен за 2023-10 — 2023-12. Найденный Google Sheets ДДС содержит операции 2023-08 — 2023-12. Актуальный банковский ДДС частично восстановлен через Sber API за `2026-02-01`–`2026-05-19`.

Источник:
`research/processed/economic_block/gs_finance_report.md`, `research/processed/sber/bank_cashflow_report.md`.

Вывод:
Google Sheets полезны как структура статей, а Sber API уже дает текущие денежные движения 2026 по расчетному счету. За `2026-02-01`–`2026-05-19` выписка содержит 640 операций, 10 693 124 руб. поступлений, 10 794 090 руб. списаний и net cashflow -100 966 руб. Все 108 дней сходятся между `summary` и `transactions`.

Действие:
расширить выгрузку Sber API на полный нужный период, разметить псевдонимы контрагентов и назначения платежей в приватной карте, затем перенести агрегаты по статьям в управленческий ДДС/P&L.

Факт:
первичная сверка банковских поступлений с iiko-выручкой показывает, что банк покрывает не всю операционную выручку: февраль 2026 - 76.5%, март - 84.3%, апрель - 76.9%, `2026-05-01`–`2026-05-17` - 77.5%.

Источник:
`research/processed/sber/bank_iiko_revenue_reconciliation.csv`.

Вывод:
банковские поступления нельзя напрямую приравнивать к выручке iiko. Разница может включать наличные, эквайринговые лаги, агрегаторов, комиссии, возвраты и невыручечные поступления.

Действие:
следующая сверка должна идти по типам оплаты и источникам поступлений, а не только по общему обороту месяца.

```text

- Курьеры
- Аренда
- Маркетинг
- Коммунальные / содержание
- Эквайринг / комиссии

```
