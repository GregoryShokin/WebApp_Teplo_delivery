# Пользовательские виды и ручные вводы

## Пользовательские виды

| Лист | Тип вида | Что показывает | Кто открывает | Для чего |
| --- | --- | --- | --- | --- |
| `График` | основной операционный экран | курьеры по строкам, даты по колонкам, статус выхода в ячейке | менеджер / руководитель доставки | планировать и контролировать ежедневный состав курьеров |
| `Статистика` | dashboard | доставки, часы, выходы, средние времена, KPI по курьерам/периодам | руководитель доставки, владелец | оценить качество доставки и загрузку курьеров |
| `Доставки` | реестр | строки доставок/заказов, длительность, курьер, order id | менеджер / расчетный агент | сверка заказов и полноты импорта |
| `Выходы` | реестр факта смен | дата, курьер, часы, признаки смены | менеджер / расчетный агент | контроль часов и выходов |
| `Курьеры` | справочник | активные курьеры и возможные сопоставления | руководитель доставки | поддерживать список людей |

## Сводные таблицы и графики

Сводные таблицы и chart metadata не удалось снять через connector. По функциональному смыслу `Статистика` является сводным dashboard-слоем. Подтвержденные расчетные показатели из локального агрегатора:

| Показатель | Источник | Куда выводится по смыслу |
| --- | --- | --- |
| количество строк доставок | `Доставки` | `Статистика` |
| уникальные order id | `Доставки.E/F` | `Статистика` |
| завершенные доставки | `Доставки.G > 0` | `Статистика` |
| сумма длительности доставок | `Доставки.G` | `Статистика` |
| количество выходов | `Выходы` | `Статистика` |
| часы выходов | `Выходы.D` | `Статистика` |
| смены `Помог` | `Выходы.G` | `Статистика` |
| статусы `Вышел`/`Не вышел` | `График` | `Статистика` |

## Ручные вводы

| Место | Что вводится руками | Кто | Когда | Комментарий |
| --- | --- | --- | --- | --- |
| `График` | статус курьера по дате: вышел/не вышел/пусто и, возможно, другие статусы | менеджер / руководитель доставки | заранее и в день смены | основной ручной операционный ввод |
| `Курьеры` | добавление/скрытие курьера, статус активности, возможное сопоставление с iiko | руководитель доставки | при найме/увольнении/ротации | должно стать `courier_profile`/`employee_role_assignment` |
| `Выходы` | корректировки часов, признака `Помог`, строк факта выхода | менеджер | после смены или при ошибке импорта | нужен audit trail в приложении |
| `Смены` | корректировки открытия/закрытия смен, если iiko не закрыл смену | менеджер | после обнаружения ошибки | в приложении это manual correction к факту смены |
| `Доставки` | ручные корректировки заказов/длительности, если импорт не совпал | менеджер / агент | при сверке | лучше не редактировать raw, а хранить correction layer |

## Места, где ручного ввода не найдено

| Данные | Статус |
| --- | --- |
| Ставки оплаты курьеров | в книге не найдены |
| Факт выплат курьерам | в книге не найден |
| Штрафы/премии курьеров | в книге не найдены |
| Коэффициенты оплаты по типу доставки | в книге не найдены |
| Связь KPI -> сумма к выплате | не найдена |

## Как это переносить в UI

| Текущий лист | Целевой UI-раздел | Редактируемые поля | Read-only поля |
| --- | --- | --- | --- |
| `График` | `Курьеры -> График` | план/статус выхода, комментарий | факт доставок и KPI дня |
| `Выходы` | `Курьеры -> Смены` | ручная correction, причина, комментарий | iiko open/close, рассчитанные часы |
| `Доставки` | `Курьеры -> Доставки` | только correction flags/notes | order id, время, статус, курьер из iiko |
| `Статистика` | `Курьеры -> KPI` | фильтры, период | расчетные KPI |
| `Курьеры` | `Штат -> Курьеры` или `Курьеры -> Справочник` | категория, активность, сопоставление, payroll-role | ФИО/iiko id из защищенного HR-слоя |

## Правила аудита для будущего приложения

- Raw iiko delivery/order/shift data не редактировать напрямую.
- Любая ручная правка должна хранить `old_value`, `new_value`, автора, время, причину.
- Персональные поля курьера показывать только ролям HR/payroll/operations с нужными правами.
- Для финансовых расчетов хранить ссылку на источник: iiko raw id, sheet snapshot id или manual correction id.
