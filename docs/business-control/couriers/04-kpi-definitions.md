# KPI курьеров

Источник KPI: листы `Доставки`, `Выходы`, `График`, `Статистика`, а также iikoServer delivery reports. В найденной книге не обнаружены ставки, выплаты и payroll-формулы курьеров, поэтому KPI ниже описывают операционное качество и нагрузку, а не расчет оплаты.

## KPI-словарь

| KPI | Формула простыми словами | Входы | Период | Порог / светофор | Влияние на оплату |
| --- | --- | --- | --- | --- | --- |
| Уникальные доставки Sheet | Количество уникальных `order_id` в `Доставки` за период | `Доставки.E/F`, `Доставки.A` | день/месяц/курьер | порог не найден | В книге не найдено |
| Строки доставок Sheet | Количество строк `Доставки` за период | `Доставки.A:G` | день/месяц | контроль дублей против уникальных заказов | Не найдено |
| Завершенные доставки Sheet | Количество строк, где длительность доставки > 0 | `Доставки.G` | день/месяц/курьер | длительность <= 0 требует проверки | Не найдено |
| Суммарная длительность доставок | Сумма `Доставки.G` | `Доставки.G` | день/месяц/курьер | не найден | Не найдено |
| Средняя длительность доставки | Суммарная длительность / завершенные доставки | `Доставки.G` | день/месяц/курьер | сравнивать с iiko `totalTime`/`onTheWayTime` targets | Не найдено |
| Часы выходов | Сумма часов в `Выходы.D` | `Выходы.A:D` | день/месяц/курьер | hours <= 0 не считать завершенным выходом | Может быть входом для оплаты, но правило оплаты не найдено |
| Завершенные выходы | Количество строк `Выходы` с часами > 0 | `Выходы.D` | день/месяц/курьер | нет | Может быть входом для оплаты, но правило не найдено |
| Выходы `Помог` | Количество строк `Выходы.G = "Помог"` | `Выходы.G` | день/месяц/курьер | отдельная категория смен | Не найдено |

| iiko courier total time | `metric.totalTime` из `/reports/delivery/couriers` по `metricType` | iiko XML | месяц/курьер | `TARGET` строки задают цель, но смысл процентов/минут требует проверки | Не найдено |
| iiko on-the-way time | `metric.onTheWayTime` из `/reports/delivery/couriers` | iiko XML | месяц/курьер | сравнивать с `TARGET` | Не найдено |
| iiko double/triple orders | `metric.doubleOrders`, `metric.tripleOrders` | iiko XML | месяц/курьер | targets есть в ответе; бизнес-смысл требует подтверждения | Не найдено |
| iiko order count metric | `metric.orderCount` | iiko XML | месяц/курьер | `AVERAGE` не равно фактическому суммарному числу заказов | Не найдено |
| Sheet vs iiko delivery delta | `unique_delivery_orders_sheet - iiko_delivery_orders` | `Доставки` + iiko OLAP `Delivery.ServiceType=COURIER` | месяц | большое расхождение требует сверки | Не найдено |
| Стоимость на доставку | `courier_payout_total / unique_delivery_orders` | выплаты + `Доставки` | месяц | не считается без выплат | Нужна для payroll/P&L, но источник выплат не найден |
| Курьерские расходы % от delivery revenue | `courier_payout_total / iiko_delivery_revenue` | выплаты + iiko revenue | месяц | бизнес-ориентир 5.3-7.5% по портрету бизнеса | P&L, но в этой книге не считается |

## Математические определения

### Уникальные доставки

```text
unique_delivery_orders(period, courier) =
    count_distinct(order_id)
    where Доставки.date in period
      and Доставки.courier = courier
```

В локальном агрегаторе `order_id` берется из колонки `F`, если она заполнена, иначе из `E`.

### Завершенные доставки

```text
completed_delivery_rows(period, courier) =
    count(rows)
    where Доставки.date in period
      and Доставки.courier = courier
      and Доставки.duration_hours > 0
```

### Средняя длительность доставки

```text
avg_delivery_duration_hours =
    sum(Доставки.duration_hours) / completed_delivery_rows
```

Если `completed_delivery_rows = 0`, показатель не выводить как 0; показывать `нет данных`.

### Часы выходов

```text
shift_hours_sum(period, courier) =
    sum(Выходы.hours)
    where Выходы.date in period
      and Выходы.courier = courier
      and Выходы.hours > 0
```

### Sheet vs iiko delta

```text
sheet_vs_iiko_delivery_orders_delta =
    unique_delivery_orders_sheet - iiko_delivery_orders
```

iiko `iiko_delivery_orders` берется из OLAP/processed delivery metrics по `Delivery.ServiceType = COURIER`, а не из `/reports/delivery/couriers.orderCount`.

## iiko `/reports/delivery/couriers`: как трактовать

Endpoint возвращает по каждому курьеру три типа строк:

| `metricType` | Как читать | Как не читать |
| --- | --- | --- |
| `AVERAGE` | средний показатель по курьеру/периоду | не суммировать как общий факт заказов |
| `MAXIMUM` | максимум показателя за период | не сравнивать с месячным итогом |
| `TARGET` | целевой/нормативный показатель | не считать фактом |

Ключевой риск: поле `orderCount` в `AVERAGE` выглядит как среднее число заказов, а не как суммарные доставки. Для фактического количества доставок использовать `Доставки` и OLAP `Delivery.ServiceType=COURIER`.

## Пороговые значения и светофор

В книге не восстановлены явные пороги conditional formatting. Рекомендуемые стартовые правила для приложения:

| Метрика | Зеленый | Желтый | Красный | Основание |
| --- | ---: | ---: | ---: | --- |
| Sheet vs iiko delta | abs(delta) <= 2% iiko orders | 2-5% | >5% | сверка полноты импорта |
| Доля завершенных доставок | >= 98% | 95-98% | <95% | длительность пустая/0 = проблема данных |
| Доля no-show | 0 | 1 | >=2 в день | операционный контроль |
| Среднее время в пути | <= target | до +10% | > +10% | iiko `TARGET` |

Эти пороги не являются подтвержденными бизнес-правилами; их нужно утвердить с владельцем/руководителем доставки.

## Связь с оплатой и payroll

Что найдено:

- В книге есть операционные входы, которые могут понадобиться для оплаты: смены, часы, доставки, выходы.
- В книге не найдены ставки, суммы выплат, штрафы, бонусы и формулы оплаты курьеров.
- В текущем P&L курьерские расходы берутся из iiko P&L preset, строка `Account.Name = Зарплата курьеров`, а не из `График курьеров`.
- В приложении уже есть payroll-role `courier`, но миграция `0018_courier_categories` заводит placeholder zero rate. Значит перед расчетом оплаты нужно внести реальные правила ставок.

Открытый вопрос: курьеры оплачиваются за смену, за заказ, смешанно, с доплатами/штрафами или через отдельный iiko/P&L расчет?
