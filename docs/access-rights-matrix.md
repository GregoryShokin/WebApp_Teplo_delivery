# Паспорт прав доступа Teplo

Документ фиксирует целевую матрицу прав доступа для проекта Teplo. Он нужен как общий источник истины для будущей реализации на серверной и клиентской частях. Реализация в коде этим документом не выполняется.

Права в матрице названы как действия человека в интерфейсе. Технические коды прав, системные переменные и англоязычные названия не используются как пользовательские названия.

## Как читать матрицу

В колонках «Собственник», «Управляющий», «Офис-менеджер», «Кассир» указано, включено ли право в должность доступа по умолчанию.

| Значение | Смысл |
| --- | --- |
| да | Право включено по умолчанию. |
| нет | Право не включено по умолчанию. |

Базовые правила:

- Собственник может всё.
- Управляющий по умолчанию работает с производственным персоналом и курьерами.
- Управляющий по умолчанию не видит администрацию и не получает данные администрации через списки, отчёты, расчёты, выгрузки и поисковые подсказки.
- Офис-менеджер по умолчанию ведёт административный, зарплатный и финансовый контур, но не управляет доступами без отдельного разрешения собственника.
- Кассир по умолчанию получает только сменные и точечные операционные права: текущая смена, курьеры на смене, торговая касса своей точки, ввод факта.
- Клиентская часть может скрывать недоступные действия, но окончательное ограничение всегда должно проверяться на сервере.

Важно: должности доступа из этой матрицы не равны должностям сотрудников и расчётным ролям зарплаты. Например, «Кассир» в матрице доступа — это набор прав пользователя, а «Кассир» в Штате — карточка сотрудника с производственной ролью «Администратор».

## Области сотрудников в Штате

| Область | Состав |
| --- | --- |
| Администрация | Управляющие, менеджеры, системные администраторы и другие непроизводственные административные сотрудники. |
| Повара | Сотрудники с должностью «Повар» и ролями сушиста, пиццериста, шаурмиста или заготовщика. |
| Кассиры | Сотрудники с должностью «Кассир», включая производственную роль «Администратор». |
| Вспомогательный персонал | Уборщицы и посудомойки. |
| Курьеры | Сотрудники с должностью «Курьер». |
| Производственный персонал | Обобщение поваров, кассиров и вспомогательного персонала. Курьеры и администрация в эту область не входят. |

## Зарплата

В зарплатном блоке ревизия отражается только как результат уже совершённого события. Отдельное обязательное право «Смотреть списания по ревизиям в расчёте зарплаты» не вводится: по умолчанию этот просмотр входит в права «Смотреть расчёты зарплаты» и «Смотреть персональные отчёты сотрудников» с теми же ограничениями по областям сотрудников и персональным суммам. Если позже потребуется скрывать списания по ревизиям отдельно от остального расчёта, это право можно выделить дополнительно без права на действия над самой ревизией.

## Ревизии

Ревизия — это источник события.
Зарплата — это место, где виден результат этого события.

Права в этом блоке управляют действиями над ревизией, исключениями, финализацией и распределением списания. Штрафы и списания по ревизии начисляются автоматически после финализации ревизии, поэтому отдельное право на ручное начисление штрафов по ревизии не создаётся.

**Срок списания.** Дата списания (`work_date`) по умолчанию равна **дате ревизии + 1 день**, поэтому штраф попадает в **следующий зарплатный период** (вторник…понедельник) и удерживается из ближайшей выплаты — фактически **примерно через неделю** после ревизии (ревизия в понедельник → `work_date` вторник → выплата в следующий вторник). Эта дата **редактируема в черновике**: списание можно перенести на любую открытую (нефинализированную) выплату (выбор из списка будущих выплат). Перенос в уже зафиксированный период запрещён.

## Открытые вопросы

1. Лимиты премий и штрафов: какие суммы управляющий и офис-менеджер могут начислять без подтверждения собственника.
2. Ревизии: должен ли управляющий видеть персональные результаты ревизий или только итог по точке и смене.
3. Ревизии: должен ли управляющий финализировать ревизию, если финализация автоматически создаёт списания в зарплате.
4. Ревизии: кто может отменять ревизию и возвращать финализированную ревизию в черновик, если такая функция будет реализована.
5. Ревизии: кто может распределять списание по нескольким зарплатам и нужны ли лимиты или подтверждение собственника.
6. Ревизии: какие правила распределения планируются и кто должен ими управлять.
7. Ревизии для офис-менеджера: подтверждено ли, что по умолчанию нужен только просмотр без импорта, редактирования и финализации.
8. Ревизии для кассира: нужен ли просмотр активных ревизий своей точки без права управления.
9. Персональные отчёты зарплаты: можно ли управляющему смотреть персональные отчёты производственного персонала и курьеров, или только свод начислений.
10. Депозиты курьеров для кассира: показывать полный баланс и историю или только сумму удержания в текущей смене.
11. Возврат депозитов курьеров: требуется ли обязательное подтверждение собственника и при каких суммах.
12. Офис-менеджер и администрация: подтверждено ли, что офис-менеджер по умолчанию может смотреть и редактировать административных сотрудников.
13. Финализированные периоды: кто может возвращать в работу зарплату, инвентаризации и учётные периоды после закрытия.
14. Торговая касса: нужна ли отдельная настройка доступа по конкретным точкам для управляющих и кассиров.
15. Справочник пользователей: должен ли офис-менеджер хотя бы смотреть список пользователей без права менять доступы.
16. Доступ к настройкам зарплаты: должен ли офис-менеджер менять ставки и правила самостоятельно или только готовить изменения для собственника.
